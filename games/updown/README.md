# 업다운 게임

> **조이필드로 통합됨 (2026-10-21)**: 이 게임은 이제 조이필드 저장소의 `games/` 아래에서 관리하고 `https://pocketgamelab.com/joyfield/games/updown/` 로 배포합니다. 통합 전 저장소 `project-updown` 는 2026-11-05 삭제했습니다(코드·이력은 이 폴더에 subtree 로 남음).
> 앱 설치·오프라인(서비스 워커·manifest)·배포는 조이필드가 맡고, 컬러 모드·언어·효과음·진동·랭킹 이름은 조이필드 공통 설정(`joyfield.*`)을 먼저 따릅니다.
> 아래의 배포·서비스 워커·주소 설명은 통합 전 기준입니다. 현재 방식은 저장소 루트 README 를 보세요.

서버 없이 동작하는 숫자 맞추기 웹앱(PWA)입니다. 숨겨진 숫자를 추측하면 UP / DOWN 힌트를 알려 주고(한 판에 한 번은 점수를 내고 온도계로 거리도 볼 수 있음), 맞힐 때까지 계속합니다. 빨리, 적게 맞힐수록 점수가 높고 범위별로 랭킹을 겨룹니다. 주소로 접속해 플레이하고, 휴대폰·PC에 앱처럼 설치할 수 있으며, 한 번 접속한 뒤에는 오프라인에서도 실행됩니다.

## 게임 규칙 (v1.11.0~)

| 범위 | 정석 횟수 | 랭킹 |
| --- | --- | --- |
| 1 ~ 50 | 6번 | 있음 |
| 1 ~ 100 | 7번 | 있음 |
| 1 ~ 200 | 8번 | 있음 |
| 직접 정하기 1 ~ (10~9999) | ⌈log2(끝+1)⌉ | 없음(연습) |

- 난이도·하트(기회 제한)는 없습니다. 맞힐 때까지 계속하고, 시작 숫자는 늘 1입니다.
- 정답보다 작으면 **UP**, 크면 **DOWN**. 힌트에 따라 가능한 범위가 좁혀져 화면에 표시됩니다.
- **온도계**(v1.14.0~, 한 판에 한 번): 온도는 자동으로 나오지 않고, 힌트 아래 [🌡️ 온도계 −300] 버튼을 눌러야 방금 넣은 숫자의 온도를 봅니다. 거리 ÷ 끝 숫자가 3% 이하(또는 2 이하)면 🔥 아주 가까워요, 10% 이하 ☀️ 가까워요, 25% 이하 🌊 조금 멀어요, 그 밖은 ❄️ 멀어요. 시도 기록의 그 줄에도 이모지로 남습니다.
  - 차감: 1~50 은 −250점, 1~100·1~200 은 −300점(시도 1번 = 100점이라 아낄 수 있는 1~2번보다 확실히 크게). 직접 정하기(연습)는 차감 없음. 결과 화면에 "🌡️ 온도계 사용 −300점"
  - 쓸 수 없음: 아직 숫자를 넣기 전, 남은 숫자가 범위의 10% 이하(1~50: 5개, 1~100: 10개, 1~200: 20개)일 때. 버튼은 흐리게 보이고 눌러서 이유를 볼 수 있습니다
  - 버튼을 누르면 설명(무엇을 알려 주는지·한 번만·차감 점수·남은 숫자 조건·시간은 계속 흐름)과 [취소]/[−300점 사용]이 있는 창이 뜹니다. 실수로 Enter 를 눌러도 깎이지 않게 처음 초점은 [취소]. 창이 떠 있는 동안에도 시간은 흐릅니다
  - 규칙은 `src/game/rules.ts` 의 `thermoStatus`·`useThermo`·`thermoCost`, 화면은 `src/main.ts` 의 `renderThermo`·`openThermo`
  - 랭킹(v1.15.0~): 온도계를 쓴 기록은 서버에 `thermo: true` 로 남고, 업다운 랭킹 창·조이필드 전체 랭킹에서 횟수·시간(또는 점수) 옆에 🌡️ 가 붙습니다. 순위는 차감된 점수 그대로. 서버 규칙이 `thermo` 가 true 면 차감까지 뺀 점수 이하인지 검사합니다. 그 전 기록에는 표시가 없습니다
- **점수** = 1000 + 100 × (정석 횟수 − 시도 횟수) − 0.1초마다 1점 − 온도계 차감(0점 아래로는 내려가지 않음). 정석 횟수는 반씩 좁히면 반드시 맞히는 횟수입니다. 예: 1~100 을 6번·25초에 맞히면 1000 + 100 − 250 = 850점. 같은 식(온도계를 썼으면 차감까지)을 Firestore 보안 규칙이 상한으로 검사합니다(`src/game/rules.ts` 의 `score`, 루트 `firestore.rules`).
- 다이얼은 힌트로 좁혀진 범위 안의 숫자만 고를 수 있어, 이미 입력한 숫자를 다시 넣는 일이 없습니다.
- 정답은 범위 안의 모든 숫자가 같은 확률로 나옵니다.

## 기능

- 시작 화면: 1~50(초록)·1~100(파랑)·1~200(빨강) 버튼과 그 범위 최고 점수, 아래에 점선 **직접 정하기** 버튼. 직접 정하기는 가운데 팝업에서 끝 숫자만 고르고(윗줄 1 ~ 입력 칸, 아랫줄 −10·−·+·+10 버튼으로 10씩·1씩, 10~9999로 맞춤), 마지막으로 고른 값을 기억합니다(`updown.custom`). 연습 판이라 랭킹·최고 점수는 남지 않습니다.
- 숫자는 가로를 꽉 채운 110° 원호 다이얼로 고릅니다(낮은 화면에서는 화면 스크롤이 생기지 않도록 비율을 지킨 채 줄어듦)(끌기, 위 숫자 상자 양옆 −/+ 로 1씩, 키보드 화살표·Page Up/Down·Home/End·Enter). 다이얼 범위는 힌트로 좁혀진 범위를 따르고 매번 왼쪽 끝(최솟값)에서 시작하며, 확인 버튼은 원호 안쪽에 있습니다.
- 게임 화면 위: 전체 범위, 지금 몇 번째 추측인지. 다이얼 바로 위에 아직 가능한 범위 알약과 **좁혀지는 숫자 막대**: 막대는 남은 범위만 꽉 채워 보여 주고(테두리는 막대색 계열로 진하게), 다이얼로 고르는 자리를 금색 점으로 따라갑니다. 남은 숫자가 20개 이하면 막대를 숫자 칸마다 눈금으로 나누고 점 대신 고른 칸을 금색으로 칠합니다. 맞히면 막대는 그대로 두고 0.38초 뒤 결과 화면으로 넘어갑니다.
- 남은 숫자가 하나가 되면 고를 것이 없으므로 자동으로 맞힙니다: UP/DOWN 연출 뒤 "남은 숫자 하나"와 그 숫자를 보여 주고 약 0.6초 뒤 그 숫자를 낸 것으로 처리합니다(시도 1번으로 셈, 시간은 하나로 좁혀진 순간에 멈춤).
- 확인 버튼은 클릭이 아니라 손을 뗄 때 바로 냅니다. 화면 전체가 확대 막기로 `touch-action: pan-x pan-y` 라 누르는 동안 손가락이 조금만 밀려도 브라우저가 스크롤로 보고 누름을 취소했기 때문입니다(버튼만 `touch-action: none`, 뗀 곳이 버튼 둘레 16px 안이면 냄).
- 첫 실행 인트로(약 1.1초): 로고·게임명이 아래에서 올라오고(0.7초), 로고의 빨강 삼각형은 위로·파랑 삼각형은 아래로 한 번 튑니다. 이어서 상단 버튼이 나타나고 범위 버튼과 직접 정하기 버튼이 차례로 떠오릅니다. 동작 줄이기 설정이면 생략
- 시도 기록은 힌트 아래 판 안에 아래부터 쌓이고(새 기록은 떠오르며 등장), 넘치면 판 안에서 스크롤되며 위로 밀려난 기록은 흐려집니다. 화면이 낮아도 기록 3줄은 늘 보이고, 부족한 높이는 다이얼이 줄어 메웁니다.
- PC 화면(가로 900px·세로 560px 이상): 시작 화면의 범위 버튼은 2열로, 게임 화면은 왼쪽에 범위·시도·막대·시도 기록, 오른쪽에 힌트·숫자 상자·다이얼을 나란히 놓고, 결과 화면 버튼은 가운데 좁게 둡니다. 화면 전체를 화면 높이에 맞춰 키워(높이 600px 기준, 예: 1920×1080 모니터 약 1.6배) 위아래를 채우고, 뒤에서 움직이는 계절 입자와 정답 색종이도 같은 배수로 키웁니다. 마우스로 다이얼을 끌거나 키보드로 플레이합니다.
- 결과 화면: 제목 자리에 **운 문구**, 그 아래 점수(가장 크게)와 최고 점수 갱신 알약(랭킹 범위만), "정답 27 · 6번 · 4.8초" 한 줄, 연습 판이면 "연습 모드 · 랭킹 미등록". 운 문구는 시도 횟수를 정석 횟수와 비교한 6단계(기적 = 1번, 대박 행운 = 3번 이상 적게, 행운 = 1~2번 적게, 정석, 아쉬움 = 1~2번 많게, 망 = 3번 이상 많게)마다 재치 있는 문구 10개 중 하나입니다(`src/i18n.ts` 의 `luck.*`). 단계마다 섞은 순서를 기기에 남겨(`updown.luck`) 차례로 꺼내므로 10개를 다 보기 전에는 같은 문구가 다시 나오지 않고, 게임을 껐다 켜도 이어집니다. 도박을 떠올리게 하는 말(로또·복권 등)은 쓰지 않습니다. 색종이가 터지고, 최고 점수를 깨면 양쪽 아래에서도 쏘아 올려 더 크게 터집니다(동작 줄이기 설정이면 생략).
- 결과 화면 **공유하기**: 결과 카드 이미지(1080×1080 PNG: 로고, 범위, 운 문구, 점수, 정답 숫자·시도·시간, 시도 기록 UP/DOWN 마지막 7칸)와 조이필드 링크를 기기 공유 창으로 보냅니다. 카드 색은 지금 스킨·컬러 모드를 따릅니다. 공유 창이 없거나 이미지를 못 보내는 브라우저(주로 PC)는 이미지를 저장하고 링크를 클립보드에 복사합니다.
- 효과음·진동: 다이얼 눈금, UP/DOWN 힌트, 아주 가까움(🔥, 두근 한 번 더), 정답마다 소리와 진동이 납니다. 소리는 파일 없이 Web Audio 로 합성하고(조이필드 공통 재생기), 진동은 지원하는 기기(주로 안드로이드)에서만 됩니다. 설정에서 각각 켜고 끌 수 있고 기본은 켬입니다(`src/audio.ts`: 목록 `sounds/catalog.json` 의 `updown/*` recipe 를 공통 `playRecipe` 로, 진동은 `Joyfield.vibrate`).
- 손맛: 다이얼을 끌면 눈금마다 약한 진동(12ms)과 숫자 상자가 통통, 범위 끝에 닿으면 툭(30ms)·다이얼이 살짝 튕김, 끄는 동안 손잡이가 커짐. 확인하면 숫자가 쾅 박히고 UP 은 아래→위, DOWN 은 위→아래로 튀어 나오며 화면도 그 방향으로 툭, 좁혀진 범위가 반짝, 막대가 줄어듦. 동작 줄이기 설정이면 움직임은 빼고 진동·소리만
- 공유 랭킹: 범위(1~50·1~100·1~200)별 TOP 10. 점수가 높을수록 위, 같으면 먼저 등록한 기록이 위입니다. 랭킹 범위 판이 TOP 10 에 들 때만(10명이 안 찼거나 10위보다 높을 때) 결과 화면 버튼 위에 **등록 카드**("랭킹 N위 진입!" + 이름 입력 + 등록, 조이필드 모든 게임 같은 카드)가 들어와, 팝업을 열지 않고 바로 영문 이니셜(최대 5자)로 등록합니다. 등록하지 않고 홈으로 가도 오른쪽 위 버튼이 **랭킹 등록**으로 강조돼 나중에 등록할 수 있습니다. 랭킹 목록에는 점수와 그 아래 작게 시도·시간이 보입니다. 기록은 Firebase Firestore 에 저장합니다(`src/online.ts`·`ranking.ts`, 랭킹 창·등록 카드는 조이필드 공통 `@joyfield/shared/ui`, 아래 [랭킹 서버](#랭킹-서버-firebase-firestore)).
- 한국어 / 영어 — 처음에는 브라우저 언어를 따르고, 시작 화면 왼쪽 위 버튼으로 전환
- 게임 중 왼쪽 위 **홈** 버튼으로 시작 화면 이동
- 오른쪽 위 **설정**: 내 기록 지우기(전체·범위별, 이 기기의 최고 점수만 지우고 온라인 랭킹은 그대로), 컬러 모드, 스킨 설정, 언어, 효과음·진동 켜기/끄기. 맨 아래에 지금 쓰는 버전이 보입니다
- 계절 스킨(봄·여름·가을·겨울): 화면 뒤에 벚꽃잎·물방울·낙엽·눈송이가 천천히 움직이고 배경·카드·팝업·버튼·다이얼 색도 계절 톤으로 바뀝니다(범위 버튼·UP/DOWN 색은 그대로). 기본값인 **자동**은 날마다 네 스킨 중 하나를 무작위로 골라 쓰고, 계절을 직접 고르면 그 스킨으로 고정됩니다(`src/skins.ts`).

설정과 기록은 브라우저 `localStorage`에 저장됩니다(`updown.scores` 범위별 최고 점수, `updown.pending2` 등록 대기, `updown.boards` 마지막 순위표(v1.21.0~, 예전 `updown.rankings2` 는 지움), `updown.custom`, `updown.theme`, `updown.skin`, `updown.lang`). v1.11.0 은 처음 열 때 예전 하트 방식 기록(`updown.best`, `updown.pending`, `updown.rankings`)을 지웁니다.

## 실행

다른 게임과 같은 Vite + TypeScript 게임입니다(v1.21.0, 2026-11-05 에 빌드 없는 정적 파일에서 옮김).

- **개발 서버**: `pnpm --filter updown dev` (http://localhost:5174/)
- **조이필드 안에서 확인**: 조이필드 루트에서 `pnpm build` → `pnpm preview`
- **테스트**: `pnpm --filter updown test` (규칙·점수·온도계·순위표)
- **휴대폰 뒤로 가기**: 플레이 중 → 일시정지 창, 일시정지 중 → 시작 화면, 결과 → 시작 화면, 시작 화면 → 조이필드(조이필드 공통 `Joyfield.back`). 앱을 내렸을 때도 일시정지하고, 멈춘 동안은 시간이 점수에 들어가지 않습니다

## 화면 문구를 고친 뒤

화면 문구(`index.html`, `src/`)에 새 글자를 넣었다면 `pnpm font`로 웹폰트를 다시 만듭니다. 웹폰트(Jua)는 용량을 줄이려고 화면에 쓰는 글자만 담고 있어, 그러지 않으면 새 글자만 기본 글꼴로 보입니다.

## 랭킹 서버 (Firebase Firestore)

GitHub Pages 는 파일만 내주는 서버라 기록을 받을 수 없어서, 랭킹만 Firebase Firestore(무료 Spark 플랜)에 저장합니다. 여러 게임이 Firebase 프로젝트 하나(`joyfield-41b5a`)를 같이 쓰고, 이 게임은 v1.21.0부터 다른 게임과 같은 **순위표 1개 = 문서 1개** 방식입니다: 범위마다 `games/updown/rankings/50` · `100` · `200` 문서에 `{ entries: [{ name, score, tries, time, thermo?, date, dev? }, ...] }`(점수 높은 순 1~10위, 같은 점수는 먼저 올린 기록이 위)를 트랜잭션으로 씁니다(`src/online.ts` → 조이필드 공통 `@joyfield/shared/rank`, Firestore lite SDK 를 처음 필요할 때 불러옴, 공통 설정 `Joyfield.FIREBASE` — 내 PC·개발 사이트는 개발 DB `joyfield-dev`, 운영 사이트는 운영 DB). 웹 앱 설정 값(apiKey)은 원래 공개되는 값이고, 저장소는 보안 규칙이 지킵니다.

1. **보안 규칙**: 루트 `firestore.rules` 의 업다운 블록(`games/updown/rankings`)을 Firebase 콘솔 → Firestore Database → 규칙 에 붙여 넣고 게시합니다(운영·개발 두 프로젝트). 새 방식은 "기존 순위표에 새 기록 1개를 끼운 것"만 받고, 점수는 시도 횟수·걸린 시간으로 낸 점수를 넘지 못하게 검사합니다.
2. **옛 방식**: v1.20 까지의 기록 1건 = 문서 1개(`games/updown/scores-50`·`100`·`200`)는 더 읽지 않고, 규칙도 2026-11-05 지웠습니다(쓰는 사람 없음). 남은 문서는 콘솔에서 지워도 됩니다.
3. **예전 기록**: v1.10 까지의 하트·난이도 기록(`games/updown/scores`)은 더 읽지 않습니다. 콘솔 → Firestore Database → 데이터 → `games` → `updown` → `scores` 를 지우면 정리됩니다(지우지 않아도 동작에는 영향 없음). 예전 복합 색인(`scores`: difficulty·tries·time·createdAt)도 지워도 됩니다.

무료 한도는 하루 읽기 5만·쓰기 2만 번이고(프로젝트를 같이 쓰는 게임이 나눠 씀), 랭킹 한 번 열 때 읽기 최대 10번입니다. 한도를 넘으면 그날만 랭킹이 멈춥니다. 서버 없이 받는 기록이라 형식·점수 상한 검사는 하지만 마음먹고 조작하는 것까지 막지는 못합니다.
