# 업다운 게임

서버 없이 동작하는 숫자 맞추기 웹앱(PWA)입니다. 숨겨진 숫자를 추측하면 UP / DOWN 힌트를 주고, 기회 안에 맞히면 승리합니다. 주소로 접속해 플레이하고, 휴대폰·PC에 앱처럼 설치할 수 있으며, 한 번 접속한 뒤에는 오프라인에서도 실행됩니다.

## 게임 규칙

| 난이도 | 범위 | 기회 |
| --- | --- | --- |
| 쉬움 | 1 ~ 50 | 6회 |
| 보통 | 1 ~ 100 | 5회 |
| 어려움 | 1 ~ 100 | 4회 |
| 최상위 | 1 ~ 200 | 3회 |

- 정답보다 작으면 **UP**, 크면 **DOWN**. 힌트에 따라 가능한 범위가 좁혀져 화면에 표시됩니다.
- 다이얼은 힌트로 좁혀진 범위 안의 숫자만 고를 수 있어, 이미 입력한 숫자를 다시 넣어 기회를 버리는 일이 없습니다.
- 정답은 범위 안의 모든 숫자가 같은 확률로 나옵니다.
- 쉬움은 이분 탐색으로 끝까지 좁히면 6회 안에 반드시 맞힐 수 있고, 보통·어려움·최상위는 운이 필요합니다.

## 기능

- 숫자는 가로를 꽉 채운 110° 원호 다이얼로 고릅니다(낮은 화면에서는 화면 스크롤이 생기지 않도록 비율을 지킨 채 줄어듦)(끌기, 위 숫자 상자 양옆 −/+ 로 1씩, 키보드 화살표·Page Up/Down·Home/End·Enter). 다이얼 범위는 힌트로 좁혀진 범위를 따르고 매번 왼쪽 끝(최솟값)에서 시작하며, 확인 버튼은 원호 안쪽에 있습니다.
- 첫 실행 인트로(약 1.1초): 로고·게임명이 아래에서 올라오고(0.7초), 로고의 빨강 삼각형은 위로·파랑 삼각형은 아래로 한 번 튑니다. 이어서 상단 버튼이 나타나고 난이도 카드가 쉬움 → 보통 → 어려움 → 최상위 순서로 떠오른 뒤 켜진 별이 하나씩 톡 켜집니다. 동작 줄이기 설정이면 생략
- 시도 기록은 힌트 아래 판 안에 아래부터 쌓이고(새 기록은 떠오르며 등장), 넘치면 판 안에서 스크롤되며 위로 밀려난 기록은 흐려집니다. 화면이 낮아도 기록 3줄은 늘 보이고, 부족한 높이는 다이얼이 줄어 메웁니다.
- PC 화면(가로 900px·세로 560px 이상): 시작 화면의 난이도 카드는 2×2로, 게임 화면은 왼쪽에 범위·기회·시도 기록, 오른쪽에 힌트·숫자 상자·다이얼을 나란히 놓고, 결과 화면 버튼은 가운데 좁게 둡니다. 화면 전체를 화면 높이에 맞춰 키워(높이 600px 기준, 예: 1920×1080 모니터 약 1.6배) 위아래를 채우고, 뒤에서 움직이는 계절 입자와 정답 색종이도 같은 배수로 키웁니다. 마우스로 다이얼을 끌거나 키보드로 플레이합니다.
- 마지막 기회가 되면 하트가 두근거리고 화면 테두리가 붉게 맥박칩니다.
- 실패하면 X 눈에 혀를 내민 어질어질한 얼굴이 비틀거립니다.
- 정답이면 색종이가 터지고, 최고 기록을 깨면 양쪽 아래에서도 쏘아 올려 더 크게 터집니다(동작 줄이기 설정이면 생략).
- 결과 화면 **공유하기**: 결과 카드 이미지(1080×1080 PNG: 로고, 난이도·범위, 정답·실패, 정답 숫자, 시도 기록 UP/DOWN)와 "몇 번 만에 성공" 문구를 기기 공유 창으로 보냅니다. 게임 링크는 문구 끝 줄에 넣어 바로 누를 수 있는 링크로 보입니다. 이미지와 문구·링크는 한 번에 같이 보냅니다(링크 미리보기는 `index.html` 의 og 태그). 받는 앱에 따라 이미지와 함께 온 글(링크)을 버리기도 합니다(카카오톡 등). 카드 색은 지금 스킨·컬러 모드를 따릅니다. 공유 창이 없거나 이미지를 못 보내는 브라우저(주로 PC)는 이미지를 저장하고 문구·링크를 클립보드에 복사합니다.
- 난이도별 최고 기록(가장 적은 시도 횟수) 저장
- 한국어 / 영어 — 처음에는 브라우저 언어를 따르고, 시작 화면 왼쪽 위 버튼으로 전환
- 게임 중 왼쪽 위 **홈** 버튼으로 시작 화면 이동
- 오른쪽 위 **설정**: 기록 리셋(전체·난이도별), 컬러 모드(기기 설정 / 라이트 / 다크, 기본은 기기 설정), 스킨 설정(자동 / 봄 / 여름 / 가을 / 겨울, 기본은 자동), 언어. 맨 아래에 지금 쓰는 버전(`sw.js` 의 `CACHE_NAME`, 예: 버전 v133)이 보여 새 버전이 반영됐는지 확인할 수 있습니다
- 계절 스킨(봄·여름·가을·겨울): 화면 뒤에 벚꽃잎·물방울·낙엽·눈송이가 천천히 움직이고 배경·카드·팝업·버튼·다이얼 색도 계절 톤으로 바뀝니다(난이도·UP/DOWN 색은 그대로). 기본값인 **자동**은 날마다 네 스킨 중 하나를 무작위로 골라(같은 날에는 같은 스킨) 쓰고, 계절을 직접 고르면 그 스킨으로 고정됩니다. 탭이 가려지면 멈추고, 동작 줄이기 설정이면 멈춘 장면만 그립니다(`js/skins.js`).

설정과 기록은 브라우저 `localStorage`에 저장됩니다(`updown.best`, `updown.theme`, `updown.skin`, `updown.lang`). 기기를 꺼도 유지되지만, 사이트 데이터를 지우거나 다른 브라우저·기기에서는 따로 저장됩니다.

## 실행

빌드가 필요 없습니다.

- **게임만 해보기**: `index.html`을 더블클릭합니다. 설치·오프라인 기능은 꺼진 상태로 열립니다.
- **웹앱 기능까지 확인하기**: 서비스 워커는 HTTPS 또는 `localhost`에서만 동작합니다.
  1. `pnpm install` (처음 한 번)
  2. `pnpm dev`
  3. 브라우저에서 `http://localhost:3000` 접속 (종료는 `Ctrl + C`)

## 설치

- **PC Chrome / Edge**: 주소창 오른쪽의 설치 아이콘
- **안드로이드 Chrome**: 메뉴 → "앱 설치" 또는 "홈 화면에 추가"
- **iOS Safari**: 공유 버튼 → "홈 화면에 추가"

## 배포 (GitHub Pages)

1. GitHub에 저장소를 만들고 이 폴더를 푸시합니다.
2. 저장소 Settings → Pages → Source를 "Deploy from a branch", 브랜치를 `main` / `(root)`로 지정합니다.
3. 잠시 뒤 `https://<사용자명>.github.io/<저장소명>/`에서 열립니다.

하위 경로에 올라가므로 모든 경로는 상대 경로로 씁니다. `/`로 시작하는 절대 경로를 쓰면 배포 후 깨집니다.

### 파일을 고친 뒤

- `sw.js` 맨 위의 `CACHE_NAME` 버전을 올립니다(`updown-v1` → `updown-v2`). 서비스 워커가 캐시 우선으로 파일을 내주기 때문에, 올리지 않으면 이미 방문한 사용자는 옛 파일을 계속 봅니다. 버전을 올리면 다음에 열 때 새 버전을 받아 화면을 한 번 새로 고칩니다(게임 중이면 홈으로 갈 때). 설치한 앱은 다시 화면에 나올 때도 새 버전을 확인합니다.
- 화면 문구(`index.html`, `js/`)에 새 글자를 넣었다면 `pnpm font`로 웹폰트를 다시 만듭니다. 웹폰트(Jua)는 용량을 줄이려고 화면에 쓰는 글자만 담고 있어, 그러지 않으면 새 글자만 기본 글꼴로 보입니다.

## 파일 구성

```
project-updown/
├── index.html              화면 구조, 아이콘 스프라이트
├── manifest.webmanifest    앱 이름, 아이콘, 실행 방식
├── sw.js                   서비스 워커 (파일 캐시, 오프라인 응답)
├── css/style.css           스타일 (색 토큰 포함)
├── js/
│   ├── game.js             게임 규칙 (DOM 을 쓰지 않는 순수 로직)
│   ├── i18n.js             화면 문구(한국어·영어)와 언어 설정
│   ├── skins.js            계절 스킨 움직이는 배경(캔버스)
│   └── app.js              화면 렌더링, 이벤트, 기록·설정 저장, 서비스 워커 등록
├── images/                 앱 아이콘 (SVG 원본 + SVG 미지원 환경용 PNG 사본)
├── fonts/                  웹폰트 Jua 서브셋과 라이선스(SIL OFL 1.1)
├── scripts/build-font.mjs  웹폰트 서브셋 생성 (`pnpm font`)
└── docs/COLORS.md          색상 레퍼런스 (팔레트, 역할 토큰, 대비 기준)
```

`index.html`, `manifest.webmanifest`, `sw.js`는 루트에 있어야 합니다. 서비스 워커는 자기 폴더 아래만 관리할 수 있어서 `js/`로 옮기면 오프라인 기능이 동작하지 않습니다.
