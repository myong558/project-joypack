# 조이팩 미니 게임 제작 기준서 (Game Playbook)

조이팩에 새 미니 게임을 만들어 넣을 때 따르는 기준입니다. **"게임 이름 + 한두 줄 설명"만 주어져도 이 문서만으로 게임 하나를 끝까지 만들 수 있게** 하는 것이 목표입니다.

이 문서는 게임이 하나 늘 때마다 고칩니다. 새 게임까지 포함한 모든 게임을 다시 보고, 공통 요소는 1·2장과 8장에, 정체성(게임에 맞게 고르는 톤·색·캐릭터 등)은 3장 등록부에 반영합니다(9장 "문서 키우기").

- 문서 버전: **1.20** (2026-10-22, 업다운 v1.10.0 · 두더지잡기 v0.12.0 · 허브 v1.15.0 기준)
- 저장소 구조·배포·서비스 워커 같은 플랫폼 설명은 루트 [README.md](../README.md)에 있습니다. 이 문서는 "게임 하나를 어떻게 만드는가"만 다룹니다.

---

## 0. 요청 하나로 게임 만들기

요청 예: `새 게임: 반응속도 — 화면이 초록으로 바뀌는 순간 최대한 빨리 누르기`

만드는 사람(사람 또는 Claude)은 아래 순서를 그대로 밟습니다.

1. **기획 한 장** (코드 전에): 4장 "기획 한 장" 양식을 채워 게임 README 맨 위에 둡니다. 설명이 짧으면 빈칸은 이 문서의 기본값으로 채우고, 채운 값은 README 에 "가정"으로 적어 둡니다.
2. **정체성 고르기**: **게임에 어울리는** 톤·글꼴·색·캐릭터·스킨·소리를 고릅니다. 3장 등록부를 보고, 기존 게임과 전체 인상이 거의 같아지지만 않게 합니다(하나하나 겹치는 것은 괜찮음).
3. **뼈대 만들기**: 5장 구조대로 `games/<id>/` 를 만듭니다. 시작·게임·결과 화면 배치를 처음 다 만들면 **화면 크기 점검 1차**(7.1 분기점 A)를 바로 돌립니다.
4. **공통 계약 지키기**: 1장의 필수 항목을 모두 넣습니다(설정, 공유, 기록 지우기, 랭킹, 오프라인, 손맛…).
5. **조이팩에 연결**: 6장 체크리스트대로 허브·규칙·목록에 연결합니다.
6. **완료 검사**: 7장을 모두 통과합니다. 화면 크기 점검 2차(7.1 분기점 C)도 여기서.
7. **문서 키우기**: 9장대로 이 문서와 3장 등록부를 고칩니다.
8. **버전·커밋**: 게임 `package.json` 버전, 커밋, 답변에 "확인 버전"을 적습니다.

> 요청에 없는 것을 크게 상상해 붙이지 않습니다. 게임 하나는 **30초~3분 안에 한 판이 끝나는** 가벼운 게임이 기본입니다.

### 0.1 새 세션에서 시작하기

새 게임은 **새 세션(대화)에서** 만듭니다. 이전 작업 대화가 길게 쌓인 세션은 매 요청마다 그 내용을 다시 읽어 토큰이 많이 들고, 오래된 맥락(이미 바뀐 코드)이 섞일 수 있습니다. 필요한 맥락은 모두 이 문서와 코드에 있습니다.

- **첫 메시지**: `새 게임: <이름> — <한두 줄 설명>` 이면 됩니다. 정체성(분위기·색)이나 모드에 바람이 있으면 덧붙입니다. 나머지는 이 문서 기본값으로 채우고 README "가정"에 적습니다.
- **처음 읽을 것**: `CLAUDE.md`(세션 시작 때 자동으로 읽힘) → 이 문서 전체 → 필요한 파일만 5.1 "참고 파일 지도"에서 골라 엽니다.
- **토큰 아끼기**:
  - 큰 파일은 통째로 읽지 않습니다(두더지잡기 `styles.css` 4,500줄·`screens.ts` 900줄, 업다운 `style.css` 2,300줄·`app.js` 1,200줄). 필요한 부분을 검색해서 그 근처만 봅니다.
  - 화면 확인은 7.1 분기점에서만 합니다.
  - 기존 게임 전체를 분석하지 않습니다. 비교·공통화는 9장 "문서 키우기" 때 한 번만 합니다.
- **끝낼 때**: 7장 완료 검사, 9장 문서 키우기, 버전·커밋·푸시(사용자가 요청할 때), 답변 끝에 "확인 버전"을 적습니다.

## 1. 모든 게임이 반드시 공유하는 것 (플랫폼 계약)

여기 있는 것은 **게임마다 다르게 만들지 않습니다.** 사용자가 어느 게임에 들어가도 같은 자리에서 같은 방식으로 찾을 수 있어야 합니다.

### 1.1 주소·파일

| 항목 | 규칙 |
| --- | --- |
| 게임 ID | 영문 소문자 한 단어(`updown`, `hammer`). **한 번 정하면 바꾸지 않음**(저장 키·랭킹 경로·주소에 쓰임) |
| 폴더 | `games/<id>/` 안에 게임에 필요한 모든 파일(글꼴·소리·이미지 포함). 밖의 파일을 불러오지 않음(공통 모듈 제외) |
| 경로 | 모두 **상대 경로**. `/` 로 시작하는 절대 경로 금지(하위 경로 배포에서 깨짐) |
| 배포 주소 | `https://myong558.github.io/project-joypack/games/<id>/` |
| 서비스 워커·manifest | 게임이 만들지 않음. `<link rel="manifest" href="../../manifest.webmanifest">` 와 `Joypack.registerSW({ root: '../../', game: '<id>' })` |
| 공통 모듈 | 빌드하는 게임: `import '@joypack/shared'`(전역 `Joypack`). 빌드 없는 게임: `<script src="../../shared/joypack.js">` 를 다른 스크립트보다 먼저 |
| og 태그 | `og:url`·`og:image` 는 위 배포 주소 기준 절대 주소, 링크 미리보기 이미지 1200×630 `og-image.png`(캐시 제외) |
| `apple-mobile-web-app-title` | `조이팩` (설치하면 조이팩 앱 하나) |

### 1.2 공통 모듈(`packages/shared/joypack.js`)로 하는 일

| 함수 | 쓰는 곳 |
| --- | --- |
| `Joypack.get(name)` / `Joypack.set(name, value)` | 공통 설정 `theme`·`lang`·`sound`·`vibrate`·`initials` 읽기·쓰기. **새 게임은 자기 키에 따로 두지 않음.** 쓰기는 **사용자가 그 설정을 바꿀 때만**(판 끝 저장 등에서 모든 설정을 다시 쓰면 다른 화면에서 바꾼 값을 덮어씀) |
| `Joypack.registerSW({ root: '../../', game: id })` | 페이지 `load` 때 한 번. 처음 열면 게임 파일 전체를 캐시 |
| `Joypack.inviteBar({ root: '../../' })` | `load` 때 한 번. 공유 링크로 바로 들어온 사람에게 "조이팩 앱으로 설치하기" 띠 |
| `Joypack.shareResult({ gameId, image, title, installText })` | 결과 화면 "기록 공유하기" 전부(1.5). 결과 `shared`·`cancelled`·`saved`·`copied`·`failed` 를 게임 문구로 알림 |
| `Joypack.shareUrl()` | 기록 공유하기에 붙이는 조이팩 주소(첫 화면 + `?from=share`). 받은 사람에게 앱 설치·홈 화면에 추가 안내가 뜸. `shareUrl(id)` 는 게임 주소 |
| `Joypack.cleanInitials(text)` | 랭킹 이름 정리(A–Z 대문자 5자) |
| `Joypack.initialsInput(input, onChange?)` | 랭킹 이름 입력 칸: A–Z 대문자 5자만 들어가고(붙여 넣기·한글 조합 포함), 휴대폰은 영문 자판(`inputmode="email"`)·대문자로 연다 |
| `Joypack.deviceLang()` | 저장된 언어가 없을 때 기본 언어(기기 언어가 한국어면 `ko`, 그 밖은 `en`, 1.4) |
| `Joypack.topIcon(name)` | 위 메뉴 아이콘 SVG(`apps`·`globe`·`trophy`·`gear`·`home`, 1.3) |
| `Joypack.trackViewport()` | 실제로 보이는 화면 높이를 `--jp-vh` 로 계속 맞춤. 화면 높이를 꽉 채우는 게임은 시작할 때 한 번(1.3) |
| `Joypack.guardBottom()` | 설치 앱이 내비게이션 바 높이를 0으로 알려 줄 때 `--jp-bottom-guard` 로 아래 여백(1.3) |
| `Joypack.viewportReport()` | 화면 높이 값들을 한 줄 글로(사용자 기기에서 잘림 원인을 찾을 때 설정 맨 아래에 잠깐 띄움) |
| `Joypack.isGameCached(id)` / `clearGameCache(id)` | 허브 설정의 오프라인 저장 표시·비우기(게임은 보통 안 씀) |

공통 모듈에 없는 기능을 두 게임 이상이 똑같이 쓰게 되면 공통 모듈로 옮깁니다(9장).

### 1.3 화면 틀

모든 게임은 **시작 → 플레이 → 결과** 세 화면입니다.

| 화면 | 반드시 있는 것 |
| --- | --- |
| 시작 | 왼쪽 위 **조이팩 게임 목록 버튼**(`../../`, 2×2 네모 아이콘) → 그 옆 **언어 전환**. 오른쪽 위 **랭킹**(있으면) → **설정**. 가운데 게임 이름·한 줄 소개·시작 버튼(모드가 여럿이면 모드별 버튼)·내 최고 기록 |
| 플레이 | 홈(시작 화면으로) 또는 일시 정지. 점수·남은 시간/기회 같은 현재 상태 |
| 결과 | 결과(점수·등급·횟수 등), 신기록 연출, **랭킹 등록 카드**(TOP 10 안이면 결과 화면 안에서 바로), **다시 하기**(가장 큰 버튼, Enter/스페이스), **기록 공유하기**(글자 있는 버튼), 홈 |

- **위 메뉴는 조이팩 공통 모양·자리**를 씁니다(1.8, 자리는 1.9부터). 버튼은 `<nav class="jp-topbar">` 안 왼쪽 `.jp-topbar-group`(조이팩·언어), 오른쪽 `.jp-topbar-group`(랭킹·설정)에 넣습니다. 메뉴 줄은 화면 맨 위에 고정(상태 표시줄 아래 16px, 좌우 16px, PC는 24px·단추 60px)이라 조이팩 → 게임으로 넘어가도 버튼이 움직이지 않습니다. 내용은 `--jp-top-space`(메뉴 아래 끝) 아래에서 시작하고, 화면을 통째로 확대(zoom)하는 게임은 `--jp-top-unzoom` 에 그 배수를 넣어 메뉴만 확대에서 뺍니다. 자리·모양만 맞추고 버튼 구성은 앱마다 필요한 것만 둡니다(조이팩 첫 화면에는 조이팩 가기 버튼이 없어 언어 버튼이 맨 왼쪽, 업다운 게임 중에는 홈 버튼 등). 모양·크기·톤은 `packages/shared/topbar.css`(`.jp-top-btn`, 글자 있는 언어·홈 버튼은 `.jp-top-pill`), 아이콘은 `Joypack.topIcon('apps' | 'globe' | 'trophy' | 'gear' | 'home')`. 랭킹·설정은 아이콘만 두고 이름은 `aria-label`로. 등록 대기는 `.is-on`(대표색 채움) 또는 `.jp-top-dot`(모서리 점). 글꼴도 공통(Jua 18px, 앱은 `Jua` 글꼴을 준비)이고, 언어 버튼 글자에는 그 언어를 `lang` 으로 답니다(한글 위치 보정). 게임은 자리와 `--jp-top-accent`(대표색)만 정하고, 화면 비율로 통째로 커지는 게임은 휴대폰(폭 390)에서 단추 50px·아이콘 26px·글자 18px이 되게 `--jp-top-size/icon/font` 를 맞추되 PC에서 64px를 넘지 않게 합니다. 불러오기: Vite 게임은 `import '@joypack/shared/topbar.css'`, 빌드 없는 게임은 `<link rel="stylesheet" href="../../shared/topbar.css">`.
- 글자를 스크립트로 채우는 게임은, 다 채우기 전에는 내용을 숨겨(`visibility: hidden`) 늦게 채워지며 화면이 덜컥 밀리지 않게 합니다(업다운 `.booting`).
- 화면 높이에 비례하는 크기(`dvh` 등)는 설치 앱에서 1~2초 뒤 높이가 조금 바뀌면 다시 계산돼 화면이 덜컥 움직입니다. 휴대폰에서는 처음 연 높이로 정해 두고 폭이 바뀔 때만 다시 잽니다(업다운 `--vh-px`, 시작 화면 여백 고정). 화면에 다 안 들어가면 줄이거나(두더지잡기 `--fit`) 안쪽 스크롤로 맞춥니다. 화면 높이를 꽉 채워 맞추는 게임은 `Joypack.trackViewport()` 를 부르고 html·body·게임 영역 높이를 `var(--jp-vh, 100dvh)` 로 둡니다(설치 앱에서 조이팩 → 게임으로 넘어올 때 css 화면 높이가 실제보다 크게 잡혀 아래가 잘리던 문제, 두더지잡기 v0.11.3에서 확인). 또 화면 맨 아래에 꼭 보여야 할 것이 있는 게임은 `Joypack.guardBottom()` 을 부르고 아래 여백을 `max(env(safe-area-inset-bottom), var(--jp-bottom-guard, 0px))` 로 둡니다(설치 앱이 내비게이션 바 높이를 0으로 알려 줄 때 대비).
- 첫 실행 인트로 연출(1~1.5초, 누르면 건너뜀, 동작 줄이기면 생략)을 둡니다.
- 결과 화면에 들어온 직후 0.6초 동안은 누름을 막아, 플레이하던 손가락이 버튼을 잘못 누르지 않게 합니다. 결과 화면에 `locked` 클래스를 0.6초 붙여 버튼·등록 카드에 `pointer-events: none`, 키보드(Enter·스페이스)도 그동안 무시합니다.

### 1.4 설정 (게임 안 설정 창)

순서와 이름을 맞춥니다. 언어와 소리·진동을 한 줄에 나란히 두어 창 높이를 줄일 때는 "컬러 모드 → 스킨 → 언어 | 소리·진동" 순서도 됩니다(업다운). **공유 버튼은 설정에 두지 않습니다**(공유는 결과 화면의 "기록 공유하기" 하나, 1.5). 허브 설정과 같은 값(`joypack.*`)을 쓰므로 어디서 바꿔도 모든 게임에 적용됩니다.

| 순서 | 항목 | 규칙 |
| --- | --- | --- |
| 1 | 컬러 모드 | 기기 설정 / 라이트 / 다크. 기본은 기기 설정 |
| 2 | 언어 | 한국어 / English. 저장값 없으면 **기기(휴대폰·PC) 설정 언어**: 한국어면 한국어, 그 밖의 언어는 모두 영어. `Joypack.deviceLang()` 을 씀(조이팩·모든 게임 같은 규칙) |
| 3 | 스킨 | **게임마다 고유한 스킨 묶음**(3장). 기본은 "자동"(날짜마다 바뀜, 같은 날은 모두 같은 스킨) |
| 4 | 소리·진동 | 효과음 켜기/끄기, 진동 켜기/끄기. **진동을 지원하지 않는 기기(아이폰 등)에는 진동 항목을 숨김.** 화면 흔들림은 설정 항목이 아님(1.7) |
| 5 | 내 기록 지우기 | 이 기기의 최고 기록·수집 기록만. **온라인 랭킹·설정·등록 대기 기록은 남김.** 확인 문구에 "온라인 랭킹은 그대로" 명시 |
| 6 | 버전 | 맨 아래 `버전 vX.Y.Z`(`package.json` version). Vite 게임은 `define` 의 `__APP_VERSION__`, 빌드 없는 게임은 코드에 `'__APP_VERSION__'` 을 두면 `scripts/build.mjs` 가 채움. 캐시 이름 등 다른 값으로 버전을 짐작하지 않음. 바로 밑에 작은 글씨로 **저작권 표기 `Joypack.COPYRIGHT`**(© 2026 Myong Bum Soo. All rights reserved.)를 그대로 넣음(문구를 게임에 직접 쓰지 않음) |

### 1.5 공유

| 공유 | 내용 | 방식 |
| --- | --- | --- |
| 기록 공유하기(결과 화면에만) | 결과 캡처 이미지 + 조이팩 설치 주소 한 줄. **결과 글은 보내지 않음**(결과는 이미지에 다 있음) | `Joypack.shareResult` 한 번으로 이미지와 주소 줄을 같이 보냄. 공유 전에 주소 줄을 클립보드에도 넣음(카카오톡처럼 이미지와 온 글을 버리는 앱 대비). 공유 창이 없으면(PC) 이미지 저장 + 주소 복사 |

- 주소는 `Joypack.shareUrl()`(조이팩 첫 화면 + `?from=share`). 받은 사람은 조이팩 설치 안내(안드로이드 "앱 설치", 아이폰 "홈 화면에 추가")를 보고 게임을 고릅니다.
- 주소 줄은 `조이팩에서 같이 해요 👉 <주소>`(i18n 키 `share.install` 을 `installText` 로 넘김). 주소는 글 안에 넣습니다(따로 `url` 로 주면 iOS 일부 앱에서 빠짐).
- 결과 카드 이미지 파일 이름: `joypack-<id>-result.png`.
- 결과 캡처 이미지에 게임 이름·핵심 결과·세부를 다 담습니다(받은 사람은 이미지만 봐도 알 수 있게).
- 알림 문구 4개를 게임 i18n 에 둡니다: 보냄(링크 복사도 해 둠) / 이미지 저장 + 링크 복사 / 링크 복사 / 실패. 취소는 알리지 않음.

### 1.6 랭킹 (온라인 TOP 10)

- Firebase 프로젝트 `joypack-c6bd2`, 경로는 `games/<id>/` 아래만.
- 이름: 영문 대문자 A–Z 1~5자(`joypack.initials` 로 미리 채움). 입력 칸은 모두 `Joypack.initialsInput` 으로 만든다(웹은 키보드 언어를 직접 못 고르므로 한국어 키보드도 영문 자판으로 바뀌는 이메일 입력 종류로 열고, 소문자는 바로 대문자로 바꾼다).
- TOP 10 안에 들 때만 결과 화면에서 이름을 받고, 등록하지 않고 넘어가면 **등록 대기**로 기기에 저장합니다(새 판·새로고침에도 남음). 모드·난이도마다 가장 좋은 기록 하나만 두고, 랭킹 창에서 나중에 올립니다. 대기 기록이 있으면 랭킹 버튼을 "랭킹 등록"으로 강조합니다.
- 새 순위표를 받았을 때 10위 밖으로 밀린 대기 기록은 버립니다. 등록에 실패하면 대기에 그대로 둡니다.
- 받은 순위표는 기기에 사본으로 두고, 오프라인이거나 실패하면 그 사본을 "연결이 안 돼요 · 마지막으로 불러온 순위예요"와 함께 보여 주고 TOP 10 판단에도 씁니다.
- 서버 요청은 **8초** 안에 답이 없으면 포기합니다(느린 망에서 멈춘 것처럼 보이지 않게).
- 열 때만 읽습니다(허브 첫 화면을 여는 것만으로는 읽지 않음).
- 내 기록 지우기는 순위표 사본·등록 대기를 지우지 않습니다(1.4).
- **새 게임의 기본 저장 방식: 순위표 1개 = 문서 1개**(`games/<id>/rankings/<board>` = `{ entries: [...] }`, 10개 이하, 트랜잭션으로 등록). 두더지잡기 방식입니다. 읽기 1번으로 TOP 10 이 오고 복합 색인이 필요 없습니다. (업다운의 "기록 1건 = 문서 1개 + 색인" 방식은 쓰지 않습니다.)
- 순위표 이름(board)은 모드·난이도별(`classic`, `daily-YYYY-MM-DD`, `easy` …).
- 규칙은 저장소의 `firestore.rules` 에 블록을 더하고 콘솔에 게시합니다.
- **숨김 미리보기(`status: "preview"`, 7.3) 동안에도 랭킹은 평소처럼 등록합니다**(등록·대기·순위표를 휴대폰에서 실제로 시험하기 위해). 게임 코드에서 따로 막지 않습니다. 허브 랭킹 창에는 미리보기를 켠 기기에서만 그 게임 탭이 보입니다. 테스트 점수는 공개 전에 지울지 정합니다(7.3).

### 1.7 손맛 (조작감) 기준

조이팩 게임은 **누를 때마다 몸으로 느껴져야** 합니다. 아래 단계를 기준으로, 게임 성격에 맞게 고릅니다.

**진동 세기표** (ms, 배열은 진동·쉼·진동…). 10ms 아래는 대부분 기기에서 느껴지지 않습니다.

| 단계 | 값 | 쓰는 곳 예 |
| --- | --- | --- |
| 눈금 | 12 | 다이얼·슬라이더 한 칸, 선택 이동 |
| 가벼운 타격 | 30~40 | 보통 맞힘, 버튼 확정, 범위 끝 닿음 |
| 좋은 타격 | 45~60 또는 `[45,30,60]` | 특별한 대상, 콤보·피버 중 |
| 큰 사건 | `[60,40,120]` | 보스·왕 쓰러뜨림, 신기록 |
| 방향 표현 | `[30,40,70]` / `[70,40,30]` | 오름 / 내림 |
| 경고 | `[90,70,90]` | 마지막 기회, 시간 얼마 안 남음 |
| 실패·폭발 | `[90,50,140]` ~ `[140,80,380]` | 폭탄, 게임 오버 |
| 성공 축하 | `[60,50,60,50,220]` | 클리어 |

**연출 체크리스트** (한 번의 "맞힘"에 3개 이상 겹치게)

- 대상: 눌림(납작 → 튀어 오름), 번쩍임(밝게 → 원래)
- 맞힌 자리: 충격 고리·섬광, 파티클(별·조각·게임 소재에 맞는 것)
- 화면: 작게 툭(아래로 1% 미만) / 크게 흔들림(큰 사건만)
- 잠깐 멈춤(hitstop) 50~160ms (빠른 반응 게임)
- 점수 팝업: 크게 튀었다가 떠오르며 사라짐
- 소리: 파일 없이 Web Audio 합성 기본(가볍고 오프라인)
- 조작 중 상태: 끄는 동안 손잡이 확대, 누르는 동안 버튼 깊게 눌림

**규칙**

- 화면 흔들림은 **설정으로 끄지 않습니다.** 기기의 "동작 줄이기"(`prefers-reduced-motion`)가 켜져 있을 때만 움직임(흔들림·튀어 오름)을 빼고, 진동·소리·색 변화는 남깁니다.
- 연출 때문에 판정·입력이 늦어지면 안 됩니다. 소리 → 진동 → DOM 연출 순으로 부르고, 위치 이동은 `transform`·`translate` 만 씁니다.

### 1.8 저장

- 기기 저장 키는 `<id>.` 로 시작(`reaction.best`). 한 키에 JSON 으로 모아도 됩니다(`<id>:v1`).
- 공통 설정(테마·언어·소리·진동·이름)은 **자기 키에 저장하지 않고** `Joypack.get/set` 만 씁니다.
- `localStorage` 실패(시크릿 창·용량)는 조용히 넘기고 게임은 계속 됩니다.
- 출처(`myong558.github.io`) 전체가 약 5MB 를 나눠 쓰므로 작게 저장합니다.

### 1.9 화면·접근성

- 휴대폰 세로가 기본. PC(가로 900px·세로 560px 이상)에서는 두 단 배치 또는 화면 높이에 맞춰 확대.
- **가로로 눕힌 휴대폰도 깨지지 않게**(1.10부터). 브라우저 바로가기·브라우저에서는 세로 고정이 안 돼 가로로도 열리고, 주소창·아래 버튼까지 빠지면 높이가 260~560px 입니다. 세로 배치를 그대로 쌓으면 버튼이 화면 밖으로 밀리므로 `(orientation: landscape) and (max-height: 559px)` 에서 두 칸(왼쪽 상태·결과, 오른쪽 조작·버튼)으로 나눕니다. 그래도 모자라는 아주 낮은 화면은 위가 잘리지 않게 위부터 놓고(`safe center`) 안쪽 스크롤. 대화 상자(설정·도감·랭킹)도 화면보다 길면 안쪽 스크롤. 폴드 펼침(거의 정사각형, 720×740·884×1004 등)도 확인합니다.
- 스크롤 없이 한 화면에 들어오게(작은 휴대폰 360×640 기준).
- 라이트·다크 둘 다. 색은 CSS 변수(토큰)로만.
- 키보드로도 플레이(Enter·스페이스·숫자·화살표), 버튼에 `aria-label`, 누르는 영역 최소 40px.
- 한국어·영어 문구는 한 파일(`i18n`)에 모으고, 영어가 길어 넘치지 않는지 확인.

## 3. 게임에 맞게 고르는 것 (정체성)

조이팩은 **같은 틀, 다른 얼굴**입니다. 1장의 틀(버튼 자리·설정 순서·공유 방식)은 같게 두고, 아래 항목은 **그 게임에 맞게** 고릅니다.

목적은 "게임마다 분위기가 똑같아 보이지 않게" 하는 것이지, 기존 게임이 쓴 것을 피하는 것이 아닙니다.

- **먼저 게임에 맞는지**를 봅니다. 이미 다른 게임이 쓴 톤·글꼴·색·스킨 묶음이라도 이 게임에 그게 맞으면 그대로 씁니다.
- 피할 것은 **전체 인상이 거의 같은 경우**뿐입니다. 예를 들어 글꼴·대표색·그림체·스킨 묶음이 모두 기존 게임 하나와 같아 색만 바꾼 복사본처럼 보이는 경우입니다.
- 한두 가지가 겹치면 나머지(주인공·배경 움직임·소리·결과 연출 등)로 그 게임만의 느낌을 냅니다.

### 3.2 새 게임 정체성 고르는 방법

게임 설명에서 **어울리는 분위기**를 먼저 정하고(예: 긴장감 있는 반응 게임 → 강한 대비·굵은 글꼴, 느긋한 퍼즐 → 부드러운 색·둥근 글꼴), 그에 맞춰 아래를 고릅니다. 아래 후보는 **고를 거리를 넓히기 위한 참고**일 뿐, 등록부에 있는 것을 다시 써도 됩니다.

- **글꼴**: 게임 분위기에 맞는 무료·상업 사용 가능 글꼴(SIL OFL 등). 기존 글꼴(Jua, 잘난체)도 가능. 그 밖의 후보: Do Hyeon, Black Han Sans, Gaegu, Gamja Flower, Hi Melody, Dongle, Sunflower, Gowun Dodum, Yeon Sung, Gugi, Single Day, Poor Story, Stylish, East Sea Dokdo. 라이선스 파일을 글꼴 옆에 둡니다.
- **대표색**: 게임 소재에 어울리는 색. 기존 대표색과 같은 계열도 괜찮지만, 그럴 때는 다른 요소(그림체·배경)로 차이를 냅니다. 참고 후보: 초록(`#1fb57a`), 청록(`#12a4b8`), 노랑·겨자(`#f2b705`), 분홍(`#ff4f8b`), 남색·밤하늘(`#2b2d6e`). 라이트·다크 양쪽 대비(본문 4.5:1)는 반드시 지킵니다.
- **주인공·그림체**: 게임 소재에 맞게. 참고: 외곽선 없는 납작 도형, 픽셀, 손그림 크레용, 둥근 3D 느낌 그라데이션, 굵은 외곽선 만화풍. "캐릭터 없음"도 선택지.
- **스킨 묶음**: 게임 소재와 어울리는 묶음. 기존 묶음(계절, 장소)도 맞으면 사용. 참고: 시간대(아침·낮·노을·밤), 날씨, 재료(종이·나무·네온·젤리), 우주 행성, 바닷속 깊이.
- **소리 결**: 게임 느낌에 맞는 파형·음역(예: 사각파 8비트, 마림바 같은 짧은 사인, 낮은 드럼).
- **배경 움직임**: 입자, 겹 스크롤, 흐르는 무늬 등 게임에 맞게. 동작 줄이기면 멈춤.
- **결과 연출**: 신기록 연출을 게임 소재에 맞게(색종이, 불꽃, 별비, 물방울 터짐…).

**마지막 확인**: 새 게임과 가장 비슷한 기존 게임을 하나 골라 나란히 떠올려 봤을 때, 글꼴·대표색·그림체·스킨 묶음이 **모두** 같다면 하나 이상을 바꿉니다. 그렇지 않으면 그대로 진행합니다.

정체성을 고르면 **3.1 등록부에 먼저 한 줄을 적고** 만듭니다.

### 7.1 화면 크기 점검 (`pnpm check:screens`)

휴대폰 브라우저·바로가기는 세로 고정이 안 되고, 주소창·아래 버튼·내비게이션 바가 화면을 깎으며, 폴드는 펼치면 거의 정사각형입니다. 이런 크기에서 화면이 깨지거나 잘리는지 사람이 하나하나 열어 보기는 어려우므로 도구로 찍어 봅니다.

- **쓰는 법**: `pnpm build` 후 `pnpm check:screens <id>`(허브는 `hub`). 크기 묶음만: `pnpm check:screens <id> landscape`(portrait | landscape | fold | pc | all). 화면 몇 개만: `pnpm check:screens <id> all result,settings`처럼 화면 이름 일부를 쉼표로.
- **찍는 크기**(`scripts/screen-check/run.mjs` 의 SIZES, 주소창·버튼을 뺀 CSS px):
  - 세로: 360×560(주소창 + 아래 버튼), 344×690(폴드 바깥 화면), 390×664(사파리)
  - 가로: 844×390(바로가기 전체), 780×300·640×290·740×260(주소창 + 버튼), 667×375·568×320(작은 폰)
  - 폴드 펼침: 720×740, 740×690, 884×1004, 1104×784
  - PC: 1366×768
  - 휴대폰 크기는 터치 기기로 흉내 냅니다(`pointer: coarse`). 그래야 PC 전용 안내가 빠져 실제 기기와 같습니다.
- **찍을 화면**: 게임 폴더의 `screen-check.mjs` 에 적습니다. `{ name, setup?, go?, reach? }`:
  - `setup`: 열기 전 저장 값(도감 채우기 등)을 넣는 JS 한 줄
  - `go(page)`: 그 화면까지 가는 동작. `page.click(선택자)`·`eval`·`wait`·`waitFor`·`reload` 를 씁니다
  - `reach: 'once'`: 결과처럼 가는 데 오래 걸리는 화면. 한 번만 가서 크기만 바꿔 가며 찍습니다(화면을 돌리는 것과 같은 상황)
  - 꼭 넣을 화면: 시작, 게임 중, 일시정지(있으면), 결과, **결과 + 랭킹 등록 칸**(가장 긴 결과, 칸을 직접 펼쳐 봄), 랭킹, 설정, 그 밖의 대화 상자(도감 등)
  - 예: `games/updown/screen-check.mjs`, `games/hammer/screen-check.mjs`
- **결과 읽기**: 콘솔에 화면 × 크기마다 한 줄씩 나옵니다.
  - `ok`: 잘린 글자·버튼이 없습니다.
  - `off`: 화면 밖으로 나갔습니다.
  - `clip by .상자`: 넘침을 숨긴 상자에 가려졌습니다.
  - `문서 스크롤`: 페이지가 스크롤됩니다. 허브처럼 일부러 그런 경우만 괜찮습니다.
  - 스크롤 상자 안에 있어 스크롤로 볼 수 있는 것은 문제로 치지 않습니다.
  - 그림은 `screen-check/<id>/_<화면>.png`(크기별 모음, git 에 안 올라감)에 남습니다.
- **고치는 기준**(1.9):
  - 가로 낮은 화면(높이 560 미만)은 두 칸으로 나눕니다.
  - 그래도 모자라는 아주 낮은 화면(260~300)은 위부터 놓고(`safe center`) 안쪽에서 스크롤합니다. 위가 잘리거나 위 메뉴 밑으로 숨으면 안 됩니다.
  - 대화 상자는 안쪽에서 스크롤합니다.
  - 화면 비율로 글자를 줄이는 게임은 내용 전체 높이(위 끝 ~ 아래 끝)로 배율을 정합니다. 글자 최소 px 때문에 줄일수록 줄바꿈이 늘 수 있으니 조금씩 줄여 가며 찾습니다(두더지잡기 `fitStart`).

**언제 돌리나 (토큰 아끼기, 만드는 중 자동으로)**

한 번 돌리면 화면 수 × 14 크기라 몇 분 걸리고, 그림을 열어 보는 데 토큰이 듭니다. 그래서 정해 둔 분기점에서만 돌리고 묻지 않고 진행합니다.

| A. 배치 첫 완성 | 시작·게임·결과 화면이 처음 다 그려졌을 때(0장 3단계 끝) | `all` 전체 | 모든 화면의 `_<화면>.png` 를 한 번씩 봄(새 게임은 처음 보는 화면이라). 고칠 것을 한꺼번에 모아 고침 |
| B. 배치를 고친 뒤 | 화면 배치(CSS 배치·글자 크기·화면 맞춤 코드)를 고쳤을 때마다 | 고친 화면 이름 + 문제였던 크기 묶음만 | 문제였던 화면의 모음 그림만 |
| C. 완료 직전 | 7장 완료 검사 | `all` 전체 | 콘솔 줄만 보고, ok 가 아닌 화면의 모음 그림만 |
| D. 다른 게임·허브·공통 모듈 수정 | 공통 위 메뉴·`joypack.js` 화면 높이·허브 배치를 바꿨을 때 | 영향받는 앱마다 `all` | ok 가 아닌 화면만 |

- 색·문구·소리·규칙·점수만 바꿨으면 돌리지 않습니다(배치가 안 바뀜). 단, 문구가 길어졌다면 그 화면만 B로 돌립니다.
- 오래 걸리므로 백그라운드로 돌리고 그동안 다른 일을 합니다.
- 결과는 콘솔 줄을 먼저 봅니다. 낱장 그림은 모음 그림에서 이상한 크기가 보일 때만 엽니다.

### 7.3 휴대폰에서 미리 확인하기 (숨김 미리보기)

완성 전 게임을 실제 조이팩 앱(설치 앱·오프라인·화면 크기)에서 확인하되 다른 사람에게는 보이지 않게 합니다.

1. `games.json` 의 `status` 를 `"preview"` 로 두고 푸시합니다. 빌드는 이 게임도 배포하고, 게임 `index.html` 의 `<html>` 에 `data-jp-preview` 를 붙입니다(`Joypack.isPreview()` 로 알 수 있음). 랭킹은 평소처럼 실제로 등록됩니다(1.6).
2. 일반 사용자의 허브에는 카드가 없고 "다음 게임" 띠에 이름만 나옵니다. 주소(`games/<id>/`)를 직접 아는 사람만 열 수 있습니다.
3. 내 휴대폰 조이팩에서 설정 → 정보의 **버전 글자를 7번 연속** 누르면 비밀번호 창이 뜨고, 맞으면 **개발자 모드** 켜기·끄기 창이 뜹니다(스위치를 고른 뒤 **확인**을 눌러야 적용, 화면에는 "개발자 모드"로 보이고, 두 창 모두 화면 가운데 창이라 키패드가 올라와도 가리지 않음). 켜면 그 기기에서 미리보기 게임 카드가 `TEST` 표시와 함께 보이고 허브 랭킹 창에도 그 게임 탭이 생깁니다. 켜고 끌 때마다 같은 방법(7번 → 비밀번호)을 거칩니다.
4. 켠 상태는 그 기기에 남습니다(`localStorage` `joypack.preview` = `on`). **설정 화면에는 미리보기용 항목을 두지 않아** 테스트 화면이 공개 화면과 같고, 켜져 있다는 표시는 첫 화면 맨 아래 버전 글자의 "조이팩"이 "개발자"로 바뀌는 것 하나뿐입니다(글자 수가 같아 배치 그대로, 버전 앞 작은 로고는 늘 보임). 비밀번호는 코드에 SHA-256 값만 있습니다(`apps/hub/src/preview.ts`). 보안 장치가 아니라 미완성 게임을 숨기는 용도입니다.
5. 확인이 끝나면 `"live"` 로 바꾸고 `added` 를 공개하는 날로 맞춥니다(그날부터 14일 NEW). 테스트하며 올린 점수는 공개 뒤 순위표에 그대로 남으므로, 지우려면 Firebase 콘솔에서 `games/<id>/rankings` 문서를 지웁니다(사람이 함).

### 7.4 정식 공개 ("○○ 정식 오픈해줘" / "○○ 11월 1일 10시 오픈 예약해줘")

개발자 모드(`status: "preview"`, 7.3)로 휴대폰 확인을 마친 게임을 모두에게 엽니다. 공개 여부는 `games.json` 이 정하고, 관리자 페이지는 두지 않습니다(로그인·규칙·오프라인 부담에 비해 관리자 한 명에게 얻는 것이 적음).

1. **공개 방법 고르기**
   - 지금 공개: `pnpm release <id>` → `status: "live"`, `added` = 오늘(한국 날짜, 그날부터 14일 NEW), `open` 삭제.
   - 공개 예약: `pnpm release <id> --at "2026-11-01 10:00"`(한국 시각) → `status` 는 `"preview"` 그대로, `open: "2026-11-01T10:00:00+09:00"`, `added` = 그 날. 그 시각 전까지 허브에는 **누를 수 없는 COMING SOON 카드**(어떤 게임인지 숨긴 물음표 상자, "○월 ○일 (요일) 시각 공개", D-day)가 맨 앞에 보이고 "다음 게임" 띠에는 이름이 나오지 않습니다. 그 시각이 되면 열려 있던 허브도 새로고침 없이 정식 카드(NEW)로 바뀌고 랭킹 창에도 탭이 생깁니다(백그라운드에서 돌아올 때도 다시 확인). 개발자 모드 기기에서는 예약 중에도 실제 카드가 TEST 로 보입니다.
   - 예약 취소: `pnpm release <id> --cancel`.
   - 스크립트는 허브 버전 patch 를 올리고 `pnpm test`·`pnpm build` 를 돌립니다(`--skip-check` 로 건너뜀). `games.json` 은 그 게임의 필드 줄만 고쳐 모양을 지킵니다.
2. **확인**: `pnpm preview` 로 첫 화면(NEW 카드 또는 COMING SOON 카드·날짜·D-day)과 랭킹 창.
3. **문서 키우기**(9장): 8장 현황표·3.1 등록부·공통화 대기 목록, README 기록. 게임 버전도 정식 공개에 맞춰 올립니다(예: 0.x → 1.0.0).
4. **테스트 점수**: 개발자 모드 동안 올린 랭킹 점수는 그대로 남습니다. 지우려면 Firebase 콘솔에서 `games/<id>/rankings` 문서를 지웁니다(사람이 함, 답변에 알림). 예약 공개라면 공개 시각 전에 지웁니다.
5. **커밋·푸시** → 자동 배포. 예약 공개는 이 배포 한 번으로 끝나고, 공개 시각에 다시 배포할 필요가 없습니다. 공개 시각이 지난 뒤 다음 작업 때 `pnpm release <id>` 를 한 번 더 돌리면 `status: "live"` 로 정리됩니다(`added` 는 공개한 날 그대로).

## 9. 문서 키우기 (게임을 추가할 때마다)

새 게임을 넣은 커밋에서 아래를 함께 합니다.

1. **모든 게임 다시 보기**: 새 게임 + 기존 게임의 설정·공유·랭킹·손맛·저장·화면 틀을 나란히 비교합니다.
2. **8장 현황표 갱신**: 새 게임 열 추가, 상태 표시 다시 매김.
3. **공통화**: 같은 코드가 두 게임 이상에 있으면 공통 모듈로 옮기거나 대기 목록에 올립니다. 옮겼으면 1.2 표에 함수 추가.
4. **기준 바꾸기**: 새 게임에서 더 나은 방법을 찾았으면 1·2장 기준을 바꾸고, 기존 게임을 맞출지 대기 목록에 적습니다.
5. **정체성 등록부(3.1)에 한 줄**: 다음 게임이 무엇이 쓰였는지 보고 전체 인상이 너무 같아지지 않게 고를 수 있도록.
