# 조이팩 미니 게임 제작 기준서 (Game Playbook)

조이팩에 새 미니 게임을 만들어 넣을 때 따르는 기준입니다. **"게임 이름 + 한두 줄 설명"만 주어져도 이 문서만으로 게임 하나를 끝까지 만들 수 있게** 하는 것이 목표입니다.

이 문서는 게임이 하나 늘 때마다 고칩니다. 새 게임까지 포함한 모든 게임을 다시 보고, 공통 요소는 1·2장과 8장에, 정체성(게임에 맞게 고르는 톤·색·캐릭터 등)은 3장 등록부에 반영합니다(9장 "문서 키우기").

- 문서 버전: **1.62** (2026-10-26, 업다운 v1.15.5 · 두더지잡기 v1.0.2 · 타임 투 플립 v1.2.0 · 온실정원 v0.5.0 · 허브 v1.33.11 기준)
- **조이팩과 모든 게임은 상업적으로 씁니다(광고, 구글 플레이·앱스토어).** 10장 "상업 배포·마켓 기준"은 모든 단계에서 지키는 필수 기준입니다.
- 저장소 구조·배포·서비스 워커 같은 플랫폼 설명은 루트 [README.md](../README.md)에 있습니다. 이 문서는 "게임 하나를 어떻게 만드는가"만 다룹니다.

## 0. 요청 하나로 게임 만들기

요청 예: `새 게임: 반응속도 — 화면이 초록으로 바뀌는 순간 최대한 빨리 누르기`

만드는 사람(사람 또는 Claude)은 아래 순서를 그대로 밟습니다.

0. **11장 먼저 읽기**: 제작자 성향(11.1)·게임성(11.2)·디자인(11.3) 기준이 첫 버전의 문턱입니다. 이 기준 없이 만든 타임 투 플립은 첫 버전 뒤 45번 넘게 고쳤습니다.
1. **기획 한 장 + 재미 설계** (코드 전에): 4장 "기획 한 장" 양식을 채워 게임 README 맨 위에 둡니다. 재미의 세 기둥·한 판 길이와 끝·난이도 곡선·치팅 막기·요소마다 이유(11.2·11.4)까지 적습니다. 이름·소재·표현이 **10장 상업 기준**에 맞는지 여기서 먼저 확인합니다(이름 상표 검색, 직접 만들 수 있는 그림·소리인지, 전체 이용가인지). 설명이 짧으면 빈칸은 이 문서의 기본값으로 채우고, 채운 값은 README 에 "가정"으로 적어 둡니다.
2. **정체성 고르기**: **게임에 어울리는** 톤·글꼴·색·캐릭터·스킨·소리·배경 움직임을 고릅니다. 그림 수준은 11.3(세련·입체, 유아틱·플랫 금지, 로고 = 게임 시연). 3장 등록부를 보고, 기존 게임과 전체 인상이 거의 같아지지만 않게 합니다(하나하나 겹치는 것은 괜찮음). **게임에 맞는 상업 이용 가능 글꼴**과 **깊이감 있는 움직이는 배경**은 필수입니다(1.10).
3. **뼈대 만들기**: 5장 구조대로 `games/<id>/` 를 만듭니다. 시작·게임·결과 화면 배치를 처음 다 만들면 **화면 크기 점검 1차**(7.1 분기점 A)를 바로 돌립니다.
4. **공통 계약 지키기**: 1장의 필수 항목을 모두 넣습니다(설정, 공유, 기록 지우기, 랭킹, 오프라인, 손맛…). 출시 전 확인 도구(11.5)도 함께.
5. **조이팩에 연결**: 6장 체크리스트대로 허브·규칙·목록에 연결합니다.
6. **완료 검사**: 7장과 **10.8 상업 기준 검사**, **11.6 첫 버전 자체 검수**를 모두 통과합니다(모의 플레이 수치·대표 화면 캡처를 직접 보고 확인). 화면 크기 점검 2차(7.1 분기점 C)도 여기서.
7. **문서 키우기**: 9장대로 이 문서와 3장 등록부를 고칩니다.
8. **버전·커밋**: 게임 `package.json` 버전, 커밋, 답변에 "확인 버전"을 적습니다.

> 요청에 없는 것을 크게 상상해 붙이지 않습니다. 게임 하나는 **30초~3분 안에 한 판이 끝나는** 가벼운 게임이 기본입니다.
> 대신 정해야 할 것(수치·그림·연출)은 사람에게 묻지 않고 11장 기준으로 **처음부터 높은 수준**으로 정합니다. "일단 단순하게 만들고 나중에 다듬기"는 하지 않습니다(고치는 대화가 처음 만드는 것보다 토큰이 훨씬 많이 듦).
> **판 생성이 오래 걸리는 게임**(풀이기·생성기로 판을 골라 넣는 퍼즐 등): 고품질 판 생성이 몇 분 넘게 걸리면 제작 중에는 **테스트하기 부담 없는 만큼만** 만듭니다(빠른 설정의 임시 판, 날마다 바뀌는 판은 2주 치 정도). 임시 판은 판 데이터·README 에 "임시"로 표시하고, 게임 규칙·화면이 거의 완성되면 **사람에게 "나머지 판(고품질) 생성"을 먼저 제안**해 승인받고 돌립니다. 정식 공개(7.4) 전에는 반드시 끝냅니다(온실정원 v0.3.0: 화분 3개 판 하나 고르는 데 몇 분씩 걸려 뒤쪽 7판을 임시 판으로 둠 → v0.7.0 에서 판마다 동시에 돌려 약 10분 만에 고품질로 바꿈).

### 0.1 새 세션에서 시작하기

새 게임은 **새 세션(대화)에서** 만듭니다. 이전 작업 대화가 길게 쌓인 세션은 매 요청마다 그 내용을 다시 읽어 토큰이 많이 들고, 오래된 맥락(이미 바뀐 코드)이 섞일 수 있습니다. 필요한 맥락은 모두 이 문서와 코드에 있습니다.

- **첫 메시지**: `새 게임: <이름> — <한두 줄 설명>` 이면 됩니다. 정체성(분위기·색)이나 모드에 바람이 있으면 덧붙입니다. 나머지는 이 문서 기본값으로 채우고 README "가정"에 적습니다.
- **처음 읽을 것**: `CLAUDE.md`(세션 시작 때 자동으로 읽힘) → 이 문서 전체(특히 **11장**) → 필요한 파일만 5.1 "참고 파일 지도"에서 골라 엽니다.
- **토큰 아끼기**:
  - 큰 파일은 통째로 읽지 않습니다(두더지잡기 `styles.css` 4,500줄·`screens.ts` 900줄, 업다운 `style.css` 2,300줄·`app.js` 1,200줄). 필요한 부분을 검색해서 그 근처만 봅니다.
  - 화면 확인은 7.1 분기점에서만 합니다.
  - 기존 게임 전체를 분석하지 않습니다. 비교·공통화는 9장 "문서 키우기" 때 한 번만 합니다.
- **끝낼 때**: 7장 완료 검사, 9장 문서 키우기, 버전·커밋·푸시(사용자가 요청할 때), 답변 끝에 "확인 버전"을 적습니다.

## 1. 모든 게임이 반드시 공유하는 것 (플랫폼 계약)

여기 있는 것은 **게임마다 다르게 만들지 않습니다.** 사용자가 어느 게임에 들어가도 같은 자리에서 같은 방식으로 찾을 수 있어야 합니다.

### 1.1 주소·파일

| 항목 | 규칙 |
| --- | --- |
| 게임 ID | 영문 소문자 한 단어(`updown`, `hammer`). **한 번 정하면 바꾸지 않음**(저장 키·랭킹 경로·주소에 쓰임) |
| 폴더 | `games/<id>/` 안에 게임에 필요한 모든 파일(글꼴·소리·이미지 포함). 밖의 파일을 불러오지 않음(공통 모듈 제외) |
| 경로 | 모두 **상대 경로**. `/` 로 시작하는 절대 경로 금지(하위 경로 배포에서 깨짐) |
| 배포 주소 | `https://myong558.github.io/project-joypack/games/<id>/` |
| 서비스 워커·manifest | 게임이 만들지 않음. `<link rel="manifest" href="../../manifest.webmanifest">` 와 `Joypack.registerSW({ root: '../../', game: '<id>' })` |
| 공통 모듈 | 빌드하는 게임: `import '@joypack/shared'`(전역 `Joypack`). 빌드 없는 게임: `<script src="../../shared/joypack.js">` 를 다른 스크립트보다 먼저 |
| og 태그 | `og:url`·`og:image` 는 위 배포 주소 기준 절대 주소, 링크 미리보기 이미지 1200×630 `og-image.png`(캐시 제외) |
| `apple-mobile-web-app-title` | `조이팩` (설치하면 조이팩 앱 하나) |

### 1.2 공통 모듈(`packages/shared/joypack.js`)로 하는 일

| 함수 | 쓰는 곳 |
| --- | --- |
| `Joypack.get(name)` / `Joypack.set(name, value)` | 공통 설정 `theme`·`lang`·`sound`·`vibrate`·`initials` 읽기·쓰기. **새 게임은 자기 키에 따로 두지 않음.** 쓰기는 **사용자가 그 설정을 바꿀 때만**(판 끝 저장 등에서 모든 설정을 다시 쓰면 다른 화면에서 바꾼 값을 덮어씀) |
| `Joypack.registerSW({ root: '../../', game: id })` | 페이지 `load` 때 한 번. 처음 열면 게임 파일 전체를 캐시 |
| `Joypack.inviteBar({ root: '../../' })` | `load` 때 한 번. 공유 링크로 바로 들어온 사람에게 "조이팩 앱으로 설치하기" 띠 |
| `Joypack.shareResult({ gameId, image, title, installText })` | 결과 화면 "기록 공유하기" 전부(1.5). 결과 `shared`·`cancelled`·`saved`·`copied`·`failed` 를 게임 문구로 알림 |
| `Joypack.shareUrl()` | 기록 공유하기에 붙이는 조이팩 주소(첫 화면 + `?from=share`). 받은 사람에게 앱 설치·홈 화면에 추가 안내가 뜸. `shareUrl(id)` 는 게임 주소 |
| `Joypack.cleanInitials(text)` | 랭킹 이름 정리(A–Z 대문자 5자) |
| `Joypack.initialsInput(input, onChange?)` | 랭킹 이름 입력 칸: A–Z 대문자 5자만 들어가고(붙여 넣기·한글 조합 포함), 휴대폰은 영문 자판(`inputmode="email"`)·대문자로 연다 |
| `Joypack.deviceLang()` | 저장된 언어가 없을 때 기본 언어(기기 언어가 한국어면 `ko`, 그 밖은 `en`, 1.4) |
| `Joypack.topIcon(name)` | 위 메뉴 아이콘 SVG(`apps`·`globe`·`trophy`·`gear`·`home`, 1.3) |
| `Joypack.trackViewport()` | 실제로 보이는 화면 높이를 `--jp-vh` 로 계속 맞춤. 화면 높이를 꽉 채우는 게임은 시작할 때 한 번(1.3) |
| `Joypack.guardBottom()` | 설치 앱이 내비게이션 바 높이를 0으로 알려 줄 때 `--jp-bottom-guard` 로 아래 여백(1.3) |
| `Joypack.viewportReport()` | 화면 높이 값들을 한 줄 글로(사용자 기기에서 잘림 원인을 찾을 때 설정 맨 아래에 잠깐 띄움) |
| `Joypack.isGameCached(id)` / `clearGameCache(id)` | 허브 설정의 오프라인 저장 표시·비우기(게임은 보통 안 씀) |

공통 모듈에 없는 기능을 두 게임 이상이 똑같이 쓰게 되면 공통 모듈로 옮깁니다(9장).

### 1.3 화면 틀

모든 게임은 **시작 → 플레이 → 결과** 세 화면입니다.

| 화면 | 반드시 있는 것 |
| --- | --- |
| 시작 | 왼쪽 위 **조이팩 게임 목록 버튼**(`../../`, 2×2 네모 아이콘) → 그 옆 **언어 전환**. 오른쪽 위 **랭킹**(있으면) → **설정**. 가운데 게임 이름·한 줄 소개·시작 버튼(모드가 여럿이면 모드별 버튼)·내 최고 기록 |
| 플레이 | 홈(시작 화면으로) 또는 일시 정지. 점수·남은 시간/기회 같은 현재 상태 |
| 결과 | 결과(점수·등급·횟수 등), 신기록 연출, **랭킹 등록 카드**(TOP 10 안이면 결과 화면 안에서 바로), **다시 하기**(가장 큰 버튼, Enter/스페이스), **기록 공유하기**(글자 있는 버튼), 홈 |

- **위 메뉴는 조이팩 공통 모양·자리**를 씁니다(1.8, 자리는 1.9부터). 버튼은 `<nav class="jp-topbar">` 안 왼쪽 `.jp-topbar-group`(조이팩·언어), 오른쪽 `.jp-topbar-group`(랭킹·설정)에 넣습니다. 메뉴 줄은 화면 맨 위에 고정(상태 표시줄 아래 16px, 좌우 16px, PC는 24px·단추 60px)이라 조이팩 → 게임으로 넘어가도 버튼이 움직이지 않습니다. 내용은 `--jp-top-space`(메뉴 아래 끝) 아래에서 시작하고, 화면을 통째로 확대(zoom)하는 게임은 `--jp-top-unzoom` 에 그 배수를 넣어 메뉴만 확대에서 뺍니다. 자리·모양만 맞추고 버튼 구성은 앱마다 필요한 것만 둡니다(조이팩 첫 화면에는 조이팩 가기 버튼이 없어 언어 버튼이 맨 왼쪽, 업다운 게임 중에는 홈 버튼 등). 모양·크기·톤은 `packages/shared/topbar.css`(`.jp-top-btn`, 글자 있는 언어·홈 버튼은 `.jp-top-pill`), 아이콘은 `Joypack.topIcon('apps' | 'globe' | 'trophy' | 'gear' | 'home')`. 랭킹·설정은 아이콘만 두고 이름은 `aria-label`로. 등록 대기는 `.is-on`(대표색 채움) 또는 `.jp-top-dot`(모서리 점). 글꼴도 공통(Jua 18px, 앱은 `Jua` 글꼴을 준비)이고, 언어 버튼 글자에는 그 언어를 `lang` 으로 답니다(한글 위치 보정). 게임은 자리와 `--jp-top-accent`(대표색)만 정하고, 화면 비율로 통째로 커지는 게임은 휴대폰(폭 390)에서 단추 50px·아이콘 26px·글자 18px이 되게 `--jp-top-size/icon/font` 를 맞추되 PC에서 64px를 넘지 않게 합니다. 불러오기: Vite 게임은 `import '@joypack/shared/topbar.css'`, 빌드 없는 게임은 `<link rel="stylesheet" href="../../shared/topbar.css">`.
- 글자를 스크립트로 채우는 게임은, 다 채우기 전에는 내용을 숨겨(`visibility: hidden`) 늦게 채워지며 화면이 덜컥 밀리지 않게 합니다(업다운 `.booting`).
- 화면 높이에 비례하는 크기(`dvh` 등)는 설치 앱에서 1~2초 뒤 높이가 조금 바뀌면 다시 계산돼 화면이 덜컥 움직입니다. 휴대폰에서는 처음 연 높이로 정해 두고 폭이 바뀔 때만 다시 잽니다(업다운 `--vh-px`, 시작 화면 여백 고정). 화면에 다 안 들어가면 줄이거나(두더지잡기 `--fit`) 안쪽 스크롤로 맞춥니다. 화면 높이를 꽉 채워 맞추는 게임은 `Joypack.trackViewport()` 를 부르고 html·body·게임 영역 높이를 `var(--jp-vh, 100dvh)` 로 둡니다(설치 앱에서 조이팩 → 게임으로 넘어올 때 css 화면 높이가 실제보다 크게 잡혀 아래가 잘리던 문제, 두더지잡기 v0.11.3에서 확인). 또 화면 맨 아래에 꼭 보여야 할 것이 있는 게임은 `Joypack.guardBottom()` 을 부르고 아래 여백을 `max(env(safe-area-inset-bottom), var(--jp-bottom-guard, 0px))` 로 둡니다(설치 앱이 내비게이션 바 높이를 0으로 알려 줄 때 대비).
- 첫 실행 인트로 연출(1~1.5초, 누르면 건너뜀, 동작 줄이기면 생략)을 둡니다.
- 결과 화면에 들어온 직후 0.6초 동안은 누름을 막아, 플레이하던 손가락이 버튼을 잘못 누르지 않게 합니다. 결과 화면에 `locked` 클래스를 0.6초 붙여 버튼·등록 카드에 `pointer-events: none`, 키보드(Enter·스페이스)도 그동안 무시합니다.
- **판을 차례로 여는 퍼즐**(정해진 판을 하나씩 깨는 게임, 온실정원)은 결과 화면의 가장 큰 단추를 "다시 하기" 대신 **"다음 판"**(Enter)으로 하고, "다시 하기"(R)는 바로 옆에 둡니다. 판을 깨는 것이 목표라 같은 판을 다시 하는 일이 드물기 때문입니다. 끝없는 판·점수 경쟁 게임은 지금처럼 "다시 하기"가 가장 큰 단추입니다.

### 1.4 설정 (게임 안 설정 창)

순서와 이름을 맞춥니다. 언어와 소리·진동을 한 줄에 나란히 두어 창 높이를 줄일 때는 "컬러 모드 → 스킨 → 언어 | 소리·진동" 순서도 됩니다(업다운). **공유 버튼은 설정에 두지 않습니다**(공유는 결과 화면의 "기록 공유하기" 하나, 1.5). 허브 설정과 같은 값(`joypack.*`)을 쓰므로 어디서 바꿔도 모든 게임에 적용됩니다.

### 1.5 공유

| 공유 | 내용 | 방식 |
| --- | --- | --- |
| 기록 공유하기(결과 화면에만) | 결과 캡처 이미지 + 조이팩 설치 주소 한 줄. **결과 글은 보내지 않음**(결과는 이미지에 다 있음) | `Joypack.shareResult` 한 번으로 이미지와 주소 줄을 같이 보냄. 공유 전에 주소 줄을 클립보드에도 넣음(카카오톡처럼 이미지와 온 글을 버리는 앱 대비). 공유 창이 없으면(PC) 이미지 저장 + 주소 복사 |

- 주소는 `Joypack.shareUrl()`(조이팩 첫 화면 + `?from=share`). 받은 사람은 조이팩 설치 안내(안드로이드 "앱 설치", 아이폰 "홈 화면에 추가")를 보고 게임을 고릅니다.
- 주소 줄은 `조이팩에서 같이 해요 👉 <주소>`(i18n 키 `share.install` 을 `installText` 로 넘김). 주소는 글 안에 넣습니다(따로 `url` 로 주면 iOS 일부 앱에서 빠짐).
- 결과 카드 이미지 파일 이름: `joypack-<id>-result.png`.
- 결과 캡처 이미지에 게임 이름·핵심 결과·세부를 다 담습니다(받은 사람은 이미지만 봐도 알 수 있게).
- 알림 문구 4개를 게임 i18n 에 둡니다: 보냄(링크 복사도 해 둠) / 이미지 저장 + 링크 복사 / 링크 복사 / 실패. 취소는 알리지 않음.

### 1.6 랭킹 (온라인 TOP 10)

- Firebase 프로젝트 `joypack-c6bd2`, 경로는 `games/<id>/` 아래만.
- 이름: 영문 대문자 A–Z 1~5자(`joypack.initials` 로 미리 채움). 입력 칸은 모두 `Joypack.initialsInput` 으로 만든다(웹은 키보드 언어를 직접 못 고르므로 한국어 키보드도 영문 자판으로 바뀌는 이메일 입력 종류로 열고, 소문자는 바로 대문자로 바꾼다).
- TOP 10 안에 들 때만 결과 화면에서 이름을 받고, 등록하지 않고 넘어가면 **등록 대기**로 기기에 저장합니다(새 판·새로고침에도 남음). 모드·난이도마다 가장 좋은 기록 하나만 두고, 랭킹 창에서 나중에 올립니다. 대기 기록이 있으면 랭킹 버튼을 "랭킹 등록"으로 강조합니다.
- 새 순위표를 받았을 때 10위 밖으로 밀린 대기 기록은 버립니다. 등록에 실패하면 대기에 그대로 둡니다.
- 받은 순위표는 기기에 사본으로 두고, 오프라인이거나 실패하면 그 사본을 "연결이 안 돼요 · 마지막으로 불러온 순위예요"와 함께 보여 주고 TOP 10 판단에도 씁니다.
- 서버 요청은 **8초** 안에 답이 없으면 포기합니다(느린 망에서 멈춘 것처럼 보이지 않게).
- 열 때만 읽습니다(허브 첫 화면을 여는 것만으로는 읽지 않음).
- 내 기록 지우기는 순위표 사본·등록 대기를 지우지 않습니다(1.4).
- **랭킹 탭(모드·난이도·범위) 고르는 기준은 조이팩 공통**입니다. 게임 랭킹 창과 조이팩 전체 랭킹이 같은 기기 저장값(`joypack.rankBoard`)을 읽고 써서, 어디서 열어도 같은 탭으로 이어집니다. 랭킹 창을 열 때 처음 탭은 `Joypack.rankTab(게임ID, 탭 목록, 기본 탭)` 으로 고릅니다.
  1. **등록 대기 기록이 있는 탭**(여럿이면 그중 최근 탭, 아니면 화면 순서로 첫 번째)
  2. **최근 탭**: 방금 한 판의 탭 또는 어디서든 마지막으로 본 탭 중 나중 것
  3. **기본 탭**: `games.json` 의 `ranking.default`
  - 게임이 할 일 세 가지: ① 판이 끝나면 `Joypack.setRankBoard(id, 그 판의 탭)`(연습 판처럼 랭킹 없는 판은 빼기) ② 랭킹 창에서 탭을 누르면 `Joypack.setRankBoard(id, 탭)` ③ 등록 대기가 바뀔 때마다(생김·등록·10위 밖으로 밀림·순위표 새로 받음, 시작할 때 한 번) `Joypack.setRankPending(id, [대기 탭…])`. 날짜마다 바뀌는 순위표(오늘의 챌린지)는 `{ board, day: 'YYYY-MM-DD' }` 로 그날만 유효하게.
  - 결과 화면의 "랭킹 보기"처럼 방금 한 판을 보여 주는 곳은 그 판의 탭으로 바로 엽니다(위 1·2와 결과가 같음).
  - 이니셜 등록 뒤 나오는 "랭킹 보기" 버튼은 가로를 꽉 채우지 않고 **최대 220px, 가운데**(`width: min(100%, 220px)`)로 둡니다. 모든 게임 같은 크기 느낌.
- **새 게임의 기본 저장 방식: 순위표 1개 = 문서 1개**(`games/<id>/rankings/<board>` = `{ entries: [...] }`, 10개 이하, 트랜잭션으로 등록). 두더지잡기 방식입니다. 읽기 1번으로 TOP 10 이 오고 복합 색인이 필요 없습니다. (업다운의 "기록 1건 = 문서 1개" 방식은 범위마다 컬렉션을 나눠 점수 하나로만 정렬해야 색인 없이 되므로, 새 게임에는 쓰지 않습니다.)
- 순위표 이름(board)은 모드·난이도별(`classic`, `daily-YYYY-MM-DD` …). 랭킹 탭 ID는 `games.json` 의 `ranking.boards[].id` 와 같게 둡니다(조이팩 전체 랭킹과 탭 기준을 같이 쓰므로).
- 규칙은 저장소의 `firestore.rules` 에 블록을 더하고 콘솔에 게시합니다.
- **숨김 미리보기(`status: "preview"`, 7.3) 동안에도 랭킹은 평소처럼 등록합니다**(등록·대기·순위표를 휴대폰에서 실제로 시험하기 위해). 게임 코드에서 따로 막지 않습니다. 허브 랭킹 창에는 미리보기를 켠 기기에서만 그 게임 탭이 보입니다. 테스트 점수는 공개 전에 지울지 정합니다(7.3).

### 1.7 손맛 (조작감) 기준

조이팩 게임은 **누를 때마다 몸으로 느껴져야** 합니다. 아래 단계를 기준으로, 게임 성격에 맞게 고릅니다.

**진동 세기표** (ms, 배열은 진동·쉼·진동…). 10ms 아래는 대부분 기기에서 느껴지지 않습니다.

| 단계 | 값 | 쓰는 곳 예 |
| --- | --- | --- |
| 눈금 | 12 | 다이얼·슬라이더 한 칸, 선택 이동 |
| 가벼운 타격 | 30~40 | 보통 맞힘, 버튼 확정, 범위 끝 닿음 |
| 좋은 타격 | 45~60 또는 `[45,30,60]` | 특별한 대상, 콤보·피버 중 |
| 큰 사건 | `[60,40,120]` | 보스·왕 쓰러뜨림, 신기록 |
| 방향 표현 | `[30,40,70]` / `[70,40,30]` | 오름 / 내림 |
| 경고 | `[90,70,90]` | 마지막 기회, 시간 얼마 안 남음 |
| 실패·폭발 | `[90,50,140]` ~ `[140,80,380]` | 폭탄, 게임 오버 |
| 성공 축하 | `[60,50,60,50,220]` | 클리어 |

**효과음·진동 목록 — 여기서 고르고, 더 좋은 것은 더해서 씀** (`sounds/catalog.json`)

- 효과음 51개(기존 3게임 39개 + 새 후보 12개)와 진동 18개(새 후보 6개)가 상황 묶음(누름·맞힘·특별·실패·큰 사건·시간·흐름·끝)별로 들어 있습니다. 항목마다 느낌·쓰는 곳·쓴 게임·합성 방법(`recipe`)이 있습니다.
- **견본 페이지**: 배포 주소 `/sounds/`(로컬은 `pnpm preview` 뒤 http://localhost:4170/project-joypack/sounds/). 휴대폰으로 열어 소리를 듣고 진동을 느껴 보고 고릅니다(허브에 연결하지 않고 미리 캐시하지 않는 제작용 페이지).
- **새 게임 만들 때**: 게임의 순간(누름·맞힘·실패·특별·시간·끝…)마다 목록에서 어울리는 소리·진동을 고르고, 게임 소리 결(정체성)에 맞게 음높이·파형을 바꿔도 됩니다. `recipe` 는 `packages/shared/sfx.js` 의 `playRecipe(ctx, recipe)` 로 그대로 울리거나(Vite 게임은 `import { playRecipe } from '@joypack/shared/sfx.js'`, 타입 `sfx.d.ts` 포함, 온실정원 `audio.ts` 가 본보기) 게임 `audio.ts` 에 옮겨 적습니다. 쓴 항목은 `usedBy` 에 게임을 더합니다.
- **목록에 없는 더 좋은 효과**를 만들었으면 같은 커밋에서 목록에 항목을 더합니다(id `<게임>/<이름>`, 아직 안 쓴 후보는 `new/<이름>`). 기존 게임에 더 잘 맞는 새 효과가 생기면 바꿔 넣는 것도 열려 있습니다(바꾼 게임 버전 올림).
- **⛔ 저작권**: 소리는 **직접 합성(`synth`) 또는 CC0 파일만**. CC0 파일은 `file`·`url`·`author`·`license` 를 적고 README 8.1·`LICENSE` 에도 기록합니다. 출처 모르는 소리·CC-BY·비상업·"무료 효과음" 사이트 자체 약관 소리, 유명 게임·기기 소리 흉내(마리오 동전·젤다 비밀·팩맨·소닉 링·윈도우·아이폰·카카오톡 알림음 등)는 쓰지 않습니다. 진동 패턴(켜짐·쉼 ms)은 창작물이 아니라 저작권이 없습니다.
- **강제 장치**: `pnpm build` 가 `scripts/check-sounds.mjs` 로 목록(출처·recipe·진동 패턴)과 배포본의 모든 소리 파일(mp3·wav·ogg 등)을 검사합니다. 목록의 CC0 항목에 없는 소리 파일이 하나라도 있으면 **빌드가 실패**합니다.

**연출 체크리스트** (한 번의 "맞힘"에 3개 이상 겹치게)

- 대상: 눌림(납작 → 튀어 오름), 번쩍임(밝게 → 원래)
- 맞힌 자리: 충격 고리·섬광, 파티클(별·조각·게임 소재에 맞는 것)
- 화면: 작게 툭(아래로 1% 미만) / 크게 흔들림(큰 사건만)
- 잠깐 멈춤(hitstop) 50~160ms (빠른 반응 게임)
- 점수 팝업: 크게 튀었다가 떠오르며 사라짐
- 소리: 파일 없이 Web Audio 합성 기본(가볍고 오프라인)
- 조작 중 상태: 끄는 동안 손잡이 확대, 누르는 동안 버튼 깊게 눌림

**규칙**

- 화면 흔들림은 **설정으로 끄지 않습니다.** 기기의 "동작 줄이기"(`prefers-reduced-motion`)가 켜져 있을 때만 움직임(흔들림·튀어 오름)을 빼고, 진동·소리·색 변화는 남깁니다.
- 연출 때문에 판정·입력이 늦어지면 안 됩니다. 소리 → 진동 → DOM 연출 순으로 부르고, 위치 이동은 `transform`·`translate` 만 씁니다.

### 1.8 저장

- 기기 저장 키는 `<id>.` 로 시작(`reaction.best`). 한 키에 JSON 으로 모아도 됩니다(`<id>:v1`).
- 공통 설정(테마·언어·소리·진동·이름)은 **자기 키에 저장하지 않고** `Joypack.get/set` 만 씁니다.
- `localStorage` 실패(시크릿 창·용량)는 조용히 넘기고 게임은 계속 됩니다.
- 출처(`myong558.github.io`) 전체가 약 5MB 를 나눠 쓰므로 작게 저장합니다.

### 1.9 화면·접근성

- 휴대폰 세로가 기본. PC(가로 900px·세로 560px 이상)에서는 두 단 배치 또는 화면 높이에 맞춰 확대.
- **터치 확대·축소는 막습니다**(모든 앱 공통): viewport 에 `maximum-scale=1, user-scalable=no`, 공통 모듈(`joypack.js` 를 불러오면 자동)이 `touch-action: pan-x pan-y` 와 iOS 용 gesture·두 손가락 touchmove 막기를 겁니다. 손가락마다 오는 pointerdown 은 그대로라 멀티 터치 입력(두더지잡기 동시 치기)은 영향이 없습니다. 새 게임 `index.html` 의 viewport 도 같은 줄로 씁니다.
- **가로로 눕힌 휴대폰도 깨지지 않게**(1.10부터). 브라우저 바로가기·브라우저에서는 세로 고정이 안 돼 가로로도 열리고, 주소창·아래 버튼까지 빠지면 높이가 260~560px 입니다. 세로 배치를 그대로 쌓으면 버튼이 화면 밖으로 밀리므로 `(orientation: landscape) and (max-height: 559px)` 에서 두 칸(왼쪽 상태·결과, 오른쪽 조작·버튼)으로 나눕니다. 그래도 모자라는 아주 낮은 화면은 위가 잘리지 않게 위부터 놓고(`safe center`) 안쪽 스크롤. 대화 상자(설정·도감·랭킹)도 화면보다 길면 안쪽 스크롤. 폴드 펼침(거의 정사각형, 720×740·884×1004 등)도 확인합니다.
- 스크롤 없이 한 화면에 들어오게(작은 휴대폰 360×640 기준).
- 라이트·다크 둘 다. 색은 CSS 변수(토큰)로만.
- 키보드로도 플레이(Enter·스페이스·숫자·화살표), 버튼에 `aria-label`, 누르는 영역 최소 40px.
- 한국어·영어 문구는 한 파일(`i18n`)에 모으고, 영어가 길어 넘치지 않는지 확인.

### 1.10 글꼴·움직이는 배경 (필수, 타임 투 플립 v0.2.0부터)

모든 게임은 **그 게임에 맞는 글꼴**과 **지루하지 않은, 깊이감 있는 움직이는 배경**을 갖습니다. 기본 글꼴(시스템 글꼴)과 멈춘 단색 배경으로 끝내지 않습니다.

**글꼴**

- **⛔ 상업적 사용이 가능한 무료 글꼴만 씁니다(예외 없음).** 목록(`fonts/catalog.json`)에 들어가는 글꼴은 모두 `licenseType` 이 허용 목록(지금은 SIL OFL 1.1 하나)이고 `free: true`·`commercial: true`·`rfn: false`(예약 글꼴 이름 없음)여야 합니다. 유료·체험판·"개인 사용 무료"·"비상업용"·웹 임베딩 금지·라이선스 원문을 못 구한 글꼴, OFL 이 아닌 자체 약관 글꼴("상업 무료"라고 적혀 있어도 약관이 바뀔 수 있음)은 목록에 넣지 않습니다. 허용 라이선스를 늘리려면 사람에게 먼저 묻습니다.
- **강제 장치**: `pnpm build` 가 끝날 때 `scripts/check-fonts.mjs` 가 목록의 모든 글꼴 조건과 배포본(`dist`)의 모든 글꼴 파일을 검사합니다. 목록 밖 글꼴(파일 이름이 목록 id 로 시작하지 않음)·조건을 못 갖춘 글꼴·라이선스 파일(`fonts/LICENSE-<이름>.txt`)이 빠진 글꼴이 하나라도 있으면 **빌드가 실패해 배포되지 않습니다**. 서브셋 스크립트도 조건을 못 갖춘 글꼴은 만들지 않고, 받은 라이선스 원문이 OFL 이 아니거나 예약 이름이 있으면 멈춥니다. 글꼴 파일 이름은 `<목록 id>-…woff2`(예: `jua-subset.woff2`)로 짓습니다.
- **조이팩 글꼴 목록 `fonts/catalog.json` 에서 고릅니다.** 라이선스(SIL OFL 1.1, 예약 글꼴 이름 없음 → 서브셋 허용)·한글 지원 범위를 검증해 둔 글꼴들이고, 역할(`body` 본문·숫자 / `display` 제목)과 분위기가 적혀 있습니다. 쓴 게임은 `usedBy` 에 더합니다.
- **목록에 게임과 맞는 글꼴이 없으면 억지로 목록 안에서 고르지 않습니다.** 게임에 어울리는 새 글꼴을 후보로 추천하고(이유·라이선스·서브셋 가능 여부·한글 지원 수), 원본의 라이선스 전문을 받아 검증한 뒤 목록에 더하고 씁니다. 사람에게 묻지 않고 진행하되 답변에 새로 더한 글꼴과 근거를 알립니다. 순수 OFL 이 아니거나 서브셋을 허용하지 않는 글꼴(예: 예전 두더지잡기의 여기어때 잘난체, 약 850 KB)은 무거워지므로 피합니다.
- **용량**: 게임당 글꼴 2개 이하, 서브셋 합계 약 220 KB 이하(지금: 타임 투 플립 70 KB, 두더지잡기 117 KB). 글꼴 파일 하나를 여러 게임이 같이 쓰지 않습니다(같이 쓰려면 모든 글자를 담아야 해 1~4 MB가 됨). 원본은 저장소에 넣지 않고 서브셋할 때 `node_modules/.cache/fonts` 에 받습니다.
- 역할을 나눠 1~2개: **본문·숫자용**(또렷하게 읽히는 글씨, 타이머·점수) + 필요하면 **제목·띠·팝업용**(게임 분위기를 내는 글씨). 예: 타임 투 플립 = Do Hyeon(본문·숫자) + Dongle Bold(제목·팝업, 둥근 장난감 느낌).
- 서브셋은 공용 스크립트로 만듭니다(허브·모든 게임 같음): `package.json` 에 `"font": "node --use-system-ca ../../scripts/font-subset.mjs <id>=src/fonts/<id>-subset.woff2 ..."`. 화면 글자만 남긴 woff2 를 `src/fonts/` 에, 라이선스 전문을 `public/fonts/LICENSE-<이름>.txt` 로 자동 복사합니다(빌드 없는 게임은 `--license-dir=fonts`). README 8.1 표·루트 `LICENSE` 에도 기록합니다(6장 9번).
- **넣는 글자(`scripts/font-text.mjs`, 모든 앱 공통)**: 기본 세트(출력 가능한 ASCII 전체, 한글 자음·모음 ㄱ~ㅣ, 자주 쓰는 기호 약 100개 ★♥→①※℃…) + 앱의 `index.html`·`src/`·`js/`·`css/`(CSS `content:` 기호 포함) + 공통 모듈(`packages/shared`) + `games.json`. 이렇게 넓혀도 글꼴 하나에 약 5~18 KB 늘어날 뿐입니다(2026-10-26: 허브 Jua 110→126 KB, 두더지잡기 119→137 KB). 한글 2,350자 전체를 넣으면 Jua 가 약 350 KB(지금의 약 3배)라 넣지 않습니다(2026-10-26 실측).
- **빠진 글자 자동 검사(필수, `scripts/check-glyphs.mjs`)**: 서브셋을 만들면 앱 폴더에 `fonts.lock.json`(넣은 글자·파일 해시·원본 글꼴에 없는 글자)이 생깁니다. `pnpm build` 가 맨 앞에서 지금 문구와 비교해, 새 글자가 생겼으면 **내 PC에서는 그 앱의 `pnpm font` 를 저절로 다시 돌리고**, CI 에서는 빌드를 실패시킵니다. 그래서 문구를 고친 뒤 다시 만든 글꼴과 `fonts.lock.json` 을 같은 커밋에 넣습니다. 원본 글꼴에 아예 없는 글자(이모지 등)는 `absent` 에 남고 기기 글꼴로 보입니다.
- **기호 채움(Jua 처럼 기호가 거의 없는 글꼴)**: Jua 는 기본 기호 93자 중 7자(★☆♥♡ 등)만 있어 … → © ① ※ · 같은 기호가 기기 글꼴로 보였습니다. 서브셋 스크립트 세 번째 칸에 `+<본문 글꼴 id>` 를 주면 그 글꼴에 없는 ASCII·기본 기호만 담은 채움 글꼴을 만듭니다(`gothic-a1-bold=src/fonts/gothic-a1-bold-symbols.woff2=+jua`, 86자 약 8 KB). CSS 에서 본문 글꼴과 **같은 `font-family` 이름·같은 굵기 설명**에 출력된 `unicode-range` 를 붙여 하나 더 선언하면 한 글꼴처럼 섞여 쓰이고, 그 기호가 화면에 나올 때만 받습니다(Chrome 에서 확인). `pnpm build` 가 CSS 의 `unicode-range` 가 `fonts.lock.json` 과 같은지도 검사합니다. 새 게임 본문 글꼴의 기호 지원 수(2026-10-26, 93자 기준): Gothic A1 92, Gowun Dodum·Gowun Batang·Dongle 86, Yeon Sung 83, Gamja Flower 81, East Sea Dokdo 67, Do Hyeon 65, Gasoek One 37, Poor Story 30, Cute Font 25, Jua·Sunflower·Black Han Sans 7, Single Day 6, Gaegu 5, Gugi 1 — 60 아래면 기호 채움을 함께 둡니다.
- **버튼·입력칸 글꼴**: 브라우저는 `button`·`input`·`select`·`textarea` 에 기본 글꼴을 써서 게임 글꼴이 빠지기 쉽습니다. 공통 `topbar.css` 가 `:where(button, input, select, textarea, option) { font-family: inherit }`(우선순위 0)로 물려받게 합니다. 새 게임도 `topbar.css` 를 꼭 불러옵니다.
- 글자가 작게·크게 그려지는 글꼴은 `@font-face` 의 `size-adjust`·`ascent-override` 로 다른 글꼴과 크기를 맞춥니다(Dongle 150%).
- 화면에 그려진 글꼴을 확인합니다: 공용 위 메뉴(`topbar.css`)는 **Jua** 로 그리므로, Jua 를 안 쓰는 게임도 언어 단추용 작은 Jua 서브셋을 둡니다(`jua=src/fonts/jua-topbar-subset.woff2=한국어`, 세 번째 칸은 넣을 글자 + ASCII). 본문 글꼴에 없는 기호(Do Hyeon 은 · … – — − 가 없음)는 `font-family` 둘째 글꼴이 대신 그리게 합니다.

**움직이는 배경**

- **층 2~3개로 깊이**: 먼 층(크고 흐린 빛망울·하늘 무늬 등, 느리게) · 중간 층 · 가까운 층(게임 소재를 닮은 작은 물체, 더 크고·빠르고·진하게). 가까울수록 크고 빠르고 진하게 하면 깊이가 생깁니다.
- **게임 소재와 이어지게**: 카드 게임이면 뒤집히며 떠오르는 카드, 두더지면 흙 언덕·구름 겹 스크롤처럼. 스킨이 있으면 색이 스킨을 따릅니다.
- **가볍게**: 요소는 20개 안팎, 움직임은 `transform`·`opacity` 만(GPU 합성, `filter: blur` 를 움직이지 않음). 배치는 고정 시드로 매번 같게.
- **⛔ 화면보다 큰 움직이는 층을 여러 장 두지 않습니다(휴대폰 깜박임).** 오로라 덩어리(80vmax)·빛 띠·화면 크기 `translate3d` 층·`background-attachment: fixed`·`backdrop-filter` 를 겹치면 휴대폰 GPU 메모리가 모자라, 스킨·테마를 바꾸거나 창을 열 때 화면 조각(설정 창 전체 등)이 1~2프레임 빠지며 깜박입니다(타임 투 플립 v0.8.6 까지 실제로 겪음). 하늘·빛·빛망울·반짝이처럼 흐린 빛은 **캔버스 한 장**에 낮은 해상도(기기 화소의 절반쯤)로 30fps 그리고, 대화상자가 열려 있으면 그리기를 멈춥니다. DOM 으로는 작은 물체(카드 등)만 움직입니다. 반투명 판은 뒤 흐림 대신 거의 불투명한 색으로.
- **게임 조작을 방해하지 않게**: 플레이 화면에서는 흐리게(예: `body:has(.screen.game) .scene { opacity: 0.4 }`) 하거나 느리게. 누름을 받지 않음(`pointer-events: none`, `aria-hidden`).
- PC 는 마우스를 따라 층마다 다른 만큼 움직이는 시차를 넣어도 좋습니다(터치 기기는 하지 않음).
- **동작 줄이기**가 켜져 있으면 멈춘 그림으로 둡니다. 애니메이션 시간을 0초로 줄이기만 하면 물체가 끝 위치(화면 밖)로 가 버리므로 `animation: none` 으로 끕니다.
- 본보기: `games/timetoflip/src/ui/scene.ts` + `styles.css` `.scene`.

### 1.11 용량 (필수, 허브 v1.30.0부터)

조이팩은 게임이 계속 늘어나므로 용량이 쌓이지 않게 세 겹으로 막습니다.

- **받는 것**: 설치 때는 허브만 미리 받고, 게임은 처음 열 때 받습니다(`scripts/sw-template.js`). 업데이트하면 옛 파일은 지웁니다.
- **크기 상한**(`scripts/check-size.mjs`, `pnpm build` 가 검사): 게임 하나 1MB 넘으면 경고·2MB 넘으면 빌드 실패, 허브(설치 때 받는 것) 400KB 경고·600KB 실패. 넘으면 큰 파일 5개를 보여 줍니다. 줄이는 법: 그림은 SVG(코드로 그림)나 webp, 글꼴은 쓰는 글자만 서브셋, 소리는 Web Audio 합성, 같은 그림을 크기별로 여러 장 넣지 않기.
- **오래 안 한 게임 자동 정리**: 게임이 `Joypack.registerSW({ game })` 로 열릴 때 마지막으로 연 시각을 `joypack.played` 에 적고, 허브가 시작할 때 60일(`Joypack.IDLE_DAYS`) 동안 열지 않은 게임의 저장본을 비웁니다(`Joypack.cleanupIdleGames`). 오프라인일 때는 지우지 않고, 최고 기록·설정은 남습니다. 새 게임도 `registerSW` 에 `game` id 를 꼭 넘깁니다.
- 게임끼리 같은 파일 함께 쓰기는 게임이 10개 이상이고 같은 큰 파일이 반복될 때만(한 파일을 고치면 모든 게임이 바뀌고, 오프라인·지우기가 복잡해짐).

## 3. 게임에 맞게 고르는 것 (정체성)

조이팩은 **같은 틀, 다른 얼굴**입니다. 1장의 틀(버튼 자리·설정 순서·공유 방식)은 같게 두고, 아래 항목은 **그 게임에 맞게** 고릅니다.

목적은 "게임마다 분위기가 똑같아 보이지 않게" 하는 것이지, 기존 게임이 쓴 것을 피하는 것이 아닙니다.

- **먼저 게임에 맞는지**를 봅니다. 이미 다른 게임이 쓴 톤·글꼴·색·스킨 묶음이라도 이 게임에 그게 맞으면 그대로 씁니다.
- 피할 것은 **전체 인상이 거의 같은 경우**뿐입니다. 예를 들어 글꼴·대표색·그림체·스킨 묶음이 모두 기존 게임 하나와 같아 색만 바꾼 복사본처럼 보이는 경우입니다.
- 한두 가지가 겹치면 나머지(주인공·배경 움직임·소리·결과 연출 등)로 그 게임만의 느낌을 냅니다.

### 3.2 새 게임 정체성 고르는 방법

게임 설명에서 **어울리는 분위기**를 먼저 정하고(예: 긴장감 있는 반응 게임 → 강한 대비·굵은 글꼴, 느긋한 퍼즐 → 부드러운 색·둥근 글꼴), 그에 맞춰 아래를 고릅니다. 아래 후보는 **고를 거리를 넓히기 위한 참고**일 뿐, 등록부에 있는 것을 다시 써도 됩니다.

- **글꼴**: `fonts/catalog.json` 에서 게임 분위기에 맞는 것을 고릅니다(1.10). 맞는 것이 없으면 새 글꼴을 추천·검증해 목록에 더합니다. 다른 게임이 쓴 글꼴도 맞으면 써도 되지만, 제목용 글꼴은 되도록 겹치지 않게 합니다(게임 인상을 가장 크게 정함).
- **대표색**: 게임 소재에 어울리는 색. 기존 대표색과 같은 계열도 괜찮지만, 그럴 때는 다른 요소(그림체·배경)로 차이를 냅니다. 참고 후보: 초록(`#1fb57a`), 청록(`#12a4b8`), 노랑·겨자(`#f2b705`), 분홍(`#ff4f8b`), 남색·밤하늘(`#2b2d6e`). 라이트·다크 양쪽 대비(본문 4.5:1)는 반드시 지킵니다.
- **주인공·그림체**: 게임 소재에 맞게. 참고: 외곽선 없는 납작 도형, 픽셀, 손그림 크레용, 둥근 3D 느낌 그라데이션, 굵은 외곽선 만화풍. "캐릭터 없음"도 선택지.
- **스킨 묶음**: 게임 소재와 어울리는 묶음. 기존 묶음(계절, 장소)도 맞으면 사용. 참고: 시간대(아침·낮·노을·밤), 날씨, 재료(종이·나무·네온·젤리), 우주 행성, 바닷속 깊이.
- **소리 결**: 게임 느낌에 맞는 파형·음역(예: 사각파 8비트, 마림바 같은 짧은 사인, 낮은 드럼).
- **배경 움직임**(필수, 1.10): 층 2~3개로 깊이를 내고 게임 소재와 이어지게. 참고: 빛망울 + 떠오르는 물체, 겹 스크롤(하늘·산·땅), 흐르는 무늬, 입자. 동작 줄이기면 멈춤.
- **결과 연출**: 신기록 연출을 게임 소재에 맞게(색종이, 불꽃, 별비, 물방울 터짐…).

**마지막 확인**: 새 게임과 가장 비슷한 기존 게임을 하나 골라 나란히 떠올려 봤을 때, 글꼴·대표색·그림체·스킨 묶음이 **모두** 같다면 하나 이상을 바꿉니다. 그렇지 않으면 그대로 진행합니다.

정체성을 고르면 **3.1 등록부에 먼저 한 줄을 적고** 만듭니다.

### 7.1 화면 크기 점검 (`pnpm check:screens`)

휴대폰 브라우저·바로가기는 세로 고정이 안 되고, 주소창·아래 버튼·내비게이션 바가 화면을 깎으며, 폴드는 펼치면 거의 정사각형입니다. 이런 크기에서 화면이 깨지거나 잘리는지 사람이 하나하나 열어 보기는 어려우므로 도구로 찍어 봅니다.

- **쓰는 법**: `pnpm build`(게임 하나만 고쳤으면 `pnpm build <id>`: 허브와 그 게임만 다시 빌드) 후 `pnpm check:screens <id>`(허브는 `hub`). **빠른 점검**: `pnpm check:screens <id> quick` = 대표 4크기(320×560 가장 작은 폰 · 740×260 가장 낮은 가로 · 884×1004 폴드 · 1366×768 PC). 크기 묶음만: `pnpm check:screens <id> landscape`(quick | portrait | landscape | fold | pc | all). 화면 몇 개만: `pnpm check:screens <id> quick result,settings`처럼 화면 이름 일부를 쉼표로.
- **빠르게 찍는 방법**: 도구는 기기의 "동작 줄이기"를 켠 상태로 열어 첫 진입 연출을 건너뛰고 0.5초만 기다립니다(모든 앱은 동작 줄이기면 연출을 빼므로 배치는 같음, 1.3). 연출 중 화면을 봐야 할 때만 `--motion`.
- **찍는 크기**(`scripts/screen-check/run.mjs` 의 SIZES, 주소창·버튼을 뺀 CSS px):
  - 세로: 320×560(가장 작은 폰·글자를 크게 쓴 안드로이드), 360×560(주소창 + 아래 버튼), 344×690(폴드 바깥 화면), 390×664(사파리)
  - 가로: 844×390(바로가기 전체), 780×300·640×290·740×260(주소창 + 버튼), 667×375·568×320(작은 폰)
  - 폴드 펼침: 720×740, 740×690, 884×1004, 1104×784
  - PC: 1366×768
  - 휴대폰 크기는 터치 기기로 흉내 냅니다(`pointer: coarse`). 그래야 PC 전용 안내가 빠져 실제 기기와 같습니다.
- **찍을 화면**: 게임 폴더의 `screen-check.mjs` 에 적습니다. `{ name, setup?, go?, reach? }`:
  - `setup`: 열기 전 저장 값(도감 채우기 등)을 넣는 JS 한 줄
  - `go(page)`: 그 화면까지 가는 동작. `page.click(선택자)`·`eval`·`wait`·`waitFor`·`reload` 를 씁니다
  - `reach: 'once'`: 결과처럼 가는 데 오래 걸리는 화면. 한 번만 가서 크기만 바꿔 가며 찍습니다(화면을 돌리는 것과 같은 상황)
  - 꼭 넣을 화면: 시작, 게임 중, 일시정지(있으면), 결과, **결과 + 랭킹 등록 칸**(가장 긴 결과, 칸을 직접 펼쳐 봄), 랭킹, 설정, 그 밖의 대화 상자(도감 등)
  - 예: `games/updown/screen-check.mjs`, `games/hammer/screen-check.mjs`
- **결과 읽기**: 콘솔에 화면 × 크기마다 한 줄씩 나옵니다.
  - `ok`: 잘린 글자·버튼이 없습니다.
  - `off`: 화면 밖으로 나갔습니다.
  - `clip by .상자`: 넘침을 숨긴 상자에 가려졌습니다.
  - `문서 스크롤`: 페이지가 스크롤됩니다. 허브처럼 일부러 그런 경우만 괜찮습니다.
  - 스크롤 상자 안에 있어 스크롤로 볼 수 있는 것은 문제로 치지 않습니다.
  - 그림은 `screen-check/<id>/_<화면>.png`(크기별 모음, git 에 안 올라감)에 남습니다.
- **고치는 기준**(1.9):
  - 가로 낮은 화면(높이 560 미만)은 두 칸으로 나눕니다.
  - 그래도 모자라는 아주 낮은 화면(260~300)은 위부터 놓고(`safe center`) 안쪽에서 스크롤합니다. 위가 잘리거나 위 메뉴 밑으로 숨으면 안 됩니다.
  - 대화 상자는 안쪽에서 스크롤합니다.
  - 화면 비율로 글자를 줄이는 게임은 내용 전체 높이(위 끝 ~ 아래 끝)로 배율을 정합니다. 글자 최소 px 때문에 줄일수록 줄바꿈이 늘 수 있으니 조금씩 줄여 가며 찾습니다(두더지잡기 `fitStart`).

**언제 돌리나 (토큰 아끼기, 만드는 중 자동으로)**

`all`(15크기)은 화면 7개 기준 약 5분 30초(연출 건너뛰기 전 8~10분), `quick`(4크기)은 약 2~2분 30초(결과 화면까지 한 판을 실제로 기다리는 시간 포함)이고, 그림을 열어 보는 데 토큰이 듭니다. 그래서 정해 둔 분기점에서만 돌리고 묻지 않고 진행합니다. **`all` 은 새 게임 첫 배치(A)와 정식 공개 직전(C)에만**, 나머지는 `quick` 입니다(2026-10-24 측정: 글꼴·문구 수정 뒤 전체 점검 세 번이 모두 ok, 실제 문제는 첫 배치 때만 나옴).

| 분기점 | 언제 | 무엇을 | 그림 보기 |
| --- | --- | --- | --- |
| A. 배치 첫 완성 | 시작·게임·결과 화면이 처음 다 그려졌을 때(0장 3단계 끝) | `all` 전체 | 모든 화면의 `_<화면>.png` 를 한 번씩 봄(새 게임은 처음 보는 화면이라). 고칠 것을 한꺼번에 모아 고침 |
| B. 배치를 고친 뒤 | 화면 배치(CSS 배치·글자 크기·글꼴·화면 맞춤 코드)를 고쳤을 때 | `quick` + 고친 화면 이름(문제였던 크기가 4크기 밖이면 그 묶음도) | 문제였던 화면의 모음 그림만 |
| C. 완료 직전 | 새 게임 7장 완료 검사, 정식 공개(7.4) 직전 | `all` 전체 | 콘솔 줄만 보고, ok 가 아닌 화면의 모음 그림만 |
| D. 다른 게임·허브·공통 모듈 수정 | 공통 위 메뉴·`joypack.js` 화면 높이·허브 배치를 바꿨을 때 | 영향받는 앱마다 `quick` | ok 가 아닌 화면만 |

- 색·문구·소리·규칙·점수만 바꿨으면 돌리지 않습니다(배치가 안 바뀜). 단, 문구가 길어졌다면 그 화면만 B로 돌립니다.
- 백그라운드로 돌리고 **기다리지 않습니다**: 그동안 문서·버전·커밋 메시지를 먼저 씁니다. 같은 작업 안에서는 고칠 것을 모아 점검을 한 번만 돌립니다.
- 결과는 콘솔 줄을 먼저 봅니다. 낱장 그림은 모음 그림에서 이상한 크기가 보일 때만 엽니다.

### 7.3 휴대폰에서 미리 확인하기 (숨김 미리보기)

완성 전 게임을 실제 조이팩 앱(설치 앱·오프라인·화면 크기)에서 확인하되 다른 사람에게는 보이지 않게 합니다.

1. `games.json` 의 `status` 를 `"preview"` 로 두고 푸시합니다. 빌드는 이 게임도 배포하고, 게임 `index.html` 의 `<html>` 에 `data-jp-preview` 를 붙입니다(`Joypack.isPreview()` 로 알 수 있음). 랭킹은 평소처럼 실제로 등록됩니다(1.6).
2. 일반 사용자의 허브에는 카드가 없고 "다음 게임" 띠에 이름만 나옵니다. 주소(`games/<id>/`)를 직접 아는 사람만 열 수 있습니다.
3. 내 휴대폰 조이팩에서 설정 → 정보의 **버전 글자를 7번 연속** 누르면 비밀번호 창이 뜨고, 맞으면 **개발자 모드** 켜기·끄기 창이 뜹니다(스위치를 고른 뒤 **확인**을 눌러야 적용, 화면에는 "개발자 모드"로 보이고, 두 창 모두 화면 가운데 창이라 키패드가 올라와도 가리지 않음). 켜면 그 기기에서 미리보기 게임 카드가 `TEST` 표시와 함께 보이고 허브 랭킹 창에도 그 게임 탭이 생깁니다. 켜고 끌 때마다 같은 방법(7번 → 비밀번호)을 거칩니다.
4. 켠 상태는 그 기기에 남습니다(`localStorage` `joypack.preview` = `on`). **설정 화면에는 미리보기용 항목을 두지 않아** 테스트 화면이 공개 화면과 같고, 켜져 있다는 표시는 첫 화면 맨 아래 버전 글자의 "조이팩"이 "개발자"로 바뀌는 것 하나뿐입니다(글자 수가 같아 배치 그대로, 버전 앞 작은 로고는 늘 보임). 비밀번호는 코드에 SHA-256 값만 있습니다(`apps/hub/src/preview.ts`). 보안 장치가 아니라 미완성 게임을 숨기는 용도입니다.
5. 확인이 끝나면 `"live"` 로 바꾸고 `added` 를 공개하는 날로 맞춥니다(그날부터 7일 NEW). 테스트하며 올린 점수는 공개 뒤 순위표에 그대로 남으므로, 지우려면 Firebase 콘솔에서 `games/<id>/rankings` 문서를 지웁니다(사람이 함).

### 7.4 정식 공개 ("○○ 정식 오픈해줘" / "○○ 11월 1일 10시 오픈 예약해줘")

개발자 모드(`status: "preview"`, 7.3)로 휴대폰 확인을 마친 게임을 모두에게 엽니다. 공개 여부는 `games.json` 이 정하고, 관리자 페이지는 두지 않습니다(로그인·규칙·오프라인 부담에 비해 관리자 한 명에게 얻는 것이 적음).

0. **임시 판 확인**: 판 데이터에 "임시" 판이 남아 있으면(0장 "판 생성이 오래 걸리는 게임") 공개 전에 사람에게 알리고 고품질 판 생성부터 끝냅니다.
1. **공개 방법 고르기**
   - 지금 공개: `pnpm release <id>` → `status: "live"`, `added` = 오늘(한국 날짜, 그날부터 7일 NEW), `open` 삭제.
   - 공개 예약: `pnpm release <id> --at "2026-11-01 10:00"`(한국 시각) → `status` 는 `"preview"` 그대로, `open: "2026-11-01T10:00:00+09:00"`, `added` = 그 날. 그 시각 전까지 허브에는 **누를 수 없는 COMING SOON 카드**(어떤 게임인지 숨긴 물음표 상자, "○월 ○일 (요일) 시각 공개", D-day)가 맨 앞에 보이고 "다음 게임" 띠에는 이름이 나오지 않습니다. 그 시각이 되면 열려 있던 허브도 새로고침 없이 정식 카드(NEW)로 바뀌고 랭킹 창에도 탭이 생깁니다(백그라운드에서 돌아올 때도 다시 확인). 개발자 모드 기기에서는 예약 중에도 실제 카드가 TEST 로 보입니다.
   - 예약 취소: `pnpm release <id> --cancel`.
   - **공개 전 단서·막기**(허브 v1.33.0, 흐림 정도 v1.33.1): 예약 카드 그림판은 공개 72시간 전까지 ? 상자, 72~48시간 흐린 아이콘(3.5px), 48~24시간 살짝 흐린 아이콘(1.8px), 24시간 전부터 또렷한 아이콘(색 그대로, 흐린 동안은 정가운데 작은 ? 상자. 첫 단계도 배치·색이 단서로 보일 만큼만)(이름·설명은 공개 전까지 숨김, 그림판은 게임 색과 무관한 고정 색 6가지(보라·청록·버건디·남색·호박·숲 초록) 중 그 게임의 `color`(공개 뒤 카드 색)와 비슷한 것을 빼고, 아이콘 바탕과 가장 잘 구분되는(밝기 대비가 가장 큰) 것을 허브 빌드가 자동 선택: `scripts/check-icons.mjs` `TEASER_BACKDROPS`·`teaserBackdrop`, 모두 비슷하면 빌드 경고). 빌드가 예약 게임 `index.html` 에 `data-jp-open` 을 적고, 공통 모듈(`gatePreview`)이 개발자 모드가 아닌 기기에서 공개 전에 주소로 들어오면 "COMING SOON" 화면만 보입니다(공개 시각에 다시 읽어 열림). 모두 기기 시계 기준이라 시계를 바꾸면 미리 볼 수 있으므로, **랭킹 등록은 `firestore.rules` 에서 서버 시각으로 공개 전 금지**합니다(예: 타임 투 플립 `ttfOpen()`). 공개 예약 시각을 바꾸면 규칙의 날짜도 같이 고치고 Firebase 콘솔에 게시합니다(사람이 함). 개발자 모드 테스트 점수도 공개 전에는 등록되지 않습니다.
   - 스크립트는 허브 버전 patch 를 올리고 `pnpm test`·`pnpm build` 를 돌립니다(`--skip-check` 로 건너뜀). `games.json` 은 그 게임의 필드 줄만 고쳐 모양을 지킵니다.
2. **확인**: `pnpm preview` 로 첫 화면(NEW 카드 또는 COMING SOON 카드·날짜·D-day)과 랭킹 창.
3. **문서 키우기**(9장): 8장 현황표·3.1 등록부·공통화 대기 목록, README 기록. 게임 버전은 **정식 공개 = v1.0.0** 입니다: 미리보기 동안 0.x.x, `pnpm release`(지금·예약)가 0.x.x 인 게임을 1.0.0 으로 올립니다. 그 뒤로는 기능 추가 minor, 수정 patch.
4. **테스트 점수**: 개발자 모드 동안 올린 랭킹 점수는 그대로 남습니다. 지우려면 Firebase 콘솔에서 `games/<id>/rankings` 문서를 지웁니다(사람이 함, 답변에 알림). 예약 공개라면 공개 시각 전에 지웁니다.
5. **커밋·푸시** → 자동 배포. 예약 공개는 이 배포 한 번으로 끝나고, 공개 시각에 다시 배포할 필요가 없습니다. 공개 시각이 지난 뒤 다음 작업 때 `pnpm release <id>` 를 한 번 더 돌리면 `status: "live"` 로 정리됩니다(`added` 는 공개한 날 그대로).

## 9. 문서 키우기 (게임을 추가할 때마다)

새 게임을 넣은 커밋에서 아래를 함께 합니다.

1. **모든 게임 다시 보기**: 새 게임 + 기존 게임의 설정·공유·랭킹·손맛·저장·화면 틀을 나란히 비교합니다.
2. **8장 현황표 갱신**: 새 게임 열 추가, 상태 표시 다시 매김.
3. **공통화**: 같은 코드가 두 게임 이상에 있으면 공통 모듈로 옮기거나 대기 목록에 올립니다. 옮겼으면 1.2 표에 함수 추가.
4. **기준 바꾸기**: 새 게임에서 더 나은 방법을 찾았으면 1·2장 기준을 바꾸고, 기존 게임을 맞출지 대기 목록에 적습니다.
5. **11장 갱신**: 첫 버전 뒤에 사람이 고친 것을 분류해 11.1 성향표·11.6 검수 목록에 더합니다(같은 수정을 다음 게임에서 되풀이하지 않게).
6. **정체성 등록부(3.1)에 한 줄**: 다음 게임이 무엇이 쓰였는지 보고 전체 인상이 너무 같아지지 않게 고를 수 있도록.
7. **글꼴·라이선스 목록 갱신**: 새로 쓴 글꼴(웹폰트)·소리·그림 등 제3자 저작물을 README 8.1 표와 루트 `LICENSE` 제3자 목록에 더하고, 더는 쓰지 않는 글꼴은 파일·라이선스·목록에서 함께 지웁니다(실제로 받는지는 `pnpm preview` 에서 `document.fonts` 로 확인).

## 10. 상업 배포·마켓 기준 (필수 · 모든 게임과 허브)

조이팩과 안의 모든 미니 게임은 **상업적으로 씁니다**(광고 수익, 구글 플레이·애플 앱스토어 등록). 그래서 이 장은 권장이 아니라 **지키지 않으면 만들지 않는 기준**입니다. 새 게임은 0장 1번(기획)에서 이 장을 먼저 확인하고, 7장 완료 검사의 "상업 기준" 항목을 모두 통과해야 공개(7.4)할 수 있습니다. 판단이 애매하면 **쓰지 않는 쪽**을 고르고 답변에 알립니다.

> 이 장은 마켓 정책과 흔한 라이선스를 바탕으로 한 제작 기준입니다. 법률 자문이 아니므로, 출시 직전과 광고·결제를 붙일 때는 마켓 최신 정책을 다시 확인합니다.

### 10.2 이름·상표

- 게임 이름(한국어·영어)은 **일반 낱말의 조합**으로 짓고, 유명 게임·상표와 같거나 비슷하게 짓지 않습니다. 예: "Whac-A-Mole"(등록 상표)과 거의 같은 "Whack-a-Mole"은 피합니다.
- 공개 전에 이름을 상표 검색합니다: 한국 [KIPRIS](https://www.kipris.or.kr), 미국 [USPTO](https://tmsearch.uspto.gov), 그리고 구글 플레이·앱스토어에서 같은 이름의 게임이 있는지. 결과를 게임 README "기획 한 장"에 한 줄 적습니다.
- 다른 회사 이름·로고·캐릭터를 게임 안에 넣지 않습니다(패러디 포함).
- **같은 장르 게임과 첫인상이 겹치지 않게** 합니다. 장르의 기본 구성(두더지 게임의 하늘·잔디·구멍 3×3 등)은 누구나 쓸 수 있지만, 이름과 화면이 함께 비슷하면 "따라 만든 게임"으로 보입니다. 공개 전에 같은 장르의 웹·마켓 게임 몇 개와 플레이 화면을 나란히 찍어 비교하고, 겹치면 **그 게임만의 표시**(이름과 이어지는 캐릭터 동작·소품·색)를 하나 두거나 이름을 바꿉니다. 예: 두더지잡기는 같은 이름·비슷한 화면의 웹 게임("Mole Bonk")이 있어 영어 이름을 Peekaboo Moles 로 바꿈.
- **고전 게임 규칙**(상자 밀기·짝 맞추기·떨어지는 블록 등)은 규칙 자체는 저작권 보호 대상이 아니라 그대로 따라도 됩니다. 대신 원작 이름(예: "Sokoban"은 등록 상표)·원작의 판 배치(레벨 디자인)·그림·소리는 쓰지 않고, 판은 직접 만든 생성기·직접 그린 배치로 채우며, 스타일(그림·소재·연출)로 그 게임만의 인상을 만듭니다. 예: 온실정원은 상자 밀기 규칙 그대로, 상자 = 테라코타 화분, 목표 칸 = 벽 창 바로 앞 햇살 자리, 판은 `tools/levelgen.ts` 로 만듦.

### 10.3 사용자가 쓰는 글(랭킹 이름 등)

- 다른 사람에게 보이는 글은 마켓에서 **사용자 생성 콘텐츠(UGC)** 로 봅니다(구글 플레이 UGC 정책, 애플 심사 지침 1.2). 그래서:
  - 랭킹 이름은 영문 대문자 1~5자로만 받고(1.6), **등록 전에 반드시 `Joypack.isAllowedName` 으로 금지어(욕설·혐오·성적 표현)를 거릅니다**. 막히면 등록 버튼을 끄거나 "쓸 수 없는 이름이에요"를 보여 줍니다(업다운·두더지잡기 방식).
  - 금지어를 더하거나 고칠 때는 `packages/shared/joypack.js` 한 곳만 고칩니다(모든 게임 공통).
  - 자유 입력 글(채팅·닉네임 길게·댓글)은 만들지 않습니다. 꼭 필요하면 신고·차단·삭제 기능과 운영 연락처가 함께 있어야 해서 별도 판단이 필요합니다.
  - 문제 있는 기록은 Firebase 콘솔에서 지웁니다(사람이 함). 마켓 등록 정보의 지원 연락처로 신고를 받습니다.

### 10.4 개인정보·데이터

- 지금 서버에 저장하는 것: 랭킹 이름(이니셜), 점수·시도·시간, 등록 시각뿐입니다. 로그인·이메일·기기 ID·위치는 받지 않습니다. 새 게임도 **이 범위를 넘지 않습니다**. 넘어야 하면 먼저 사람에게 묻습니다.
- 그 밖의 기록·설정은 기기 `localStorage` 에만 둡니다.
- 마켓에 올리려면 필요합니다(출시 준비 때 한 번, 게임마다가 아님): 개인정보 처리방침 페이지(공개 URL), 구글 플레이 "데이터 보안" 양식, 앱스토어 "개인정보 보호 라벨". 새 게임이 저장 항목을 바꾸면 이 세 곳을 함께 고칩니다.
- **광고를 붙이면** 광고 SDK 가 광고 ID 등을 모으므로: 처리방침에 광고 항목, 유럽 등 동의 창(구글 UMP 등), iOS 는 추적 허가 창(ATT), 데이터 보안 양식 갱신이 필요합니다.
- 어린이(만 13세 미만)를 주 대상으로 홍보하지 않습니다(구글 "가족" 정책·COPPA 의 추가 제한을 받지 않도록). 그림체가 귀엽더라도 마켓 대상 연령은 "13세 이상 포함 전체"로 둡니다.

### 10.5 내용·연령 등급

- 목표 등급: **전체 이용가**(IARC 설문 기준). 그래서 피 표현, 실감 나는 폭력, 공포, 성적 표현, 술·담배·약물, 혐오 표현을 넣지 않습니다. 두더지를 뿅망치로 톡 치는 정도의 만화 같은 표현은 괜찮습니다.
- **도박처럼 보이는 요소를 넣지 않습니다**: 현금·현금성 보상, 돈으로 사는 확률형 뽑기, 카지노·슬롯 모양. 게임 안 확률 보상은 무료 플레이 보상만.
- 실존 인물·국가·종교·정치를 소재로 삼지 않습니다.

### 10.6 마켓 등록 방식 (출시 준비 때)

- **구글 플레이**: PWA 를 TWA(Trusted Web Activity, Bubblewrap 등)로 감싸 올릴 수 있습니다. `assetlinks.json` 으로 사이트 소유를 증명하고, 오프라인·설치·아이콘 기준은 지금 PWA 구성이 이미 맞춥니다.
- **애플 앱스토어**: 웹을 감싸기만 한 앱은 심사 지침 4.2(최소 기능)로 거절될 수 있습니다. Capacitor 등으로 감싸고 앱다운 기능(진동·오프라인·알림·홈 위젯 등)을 함께 두는 것을 기본으로 합니다. 앱 안의 HTML5 미니 게임은 지침 4.7 조건(모든 게임이 심사 지침을 지킬 것 등)을 따릅니다.
- 앱 안에서 디지털 상품을 팔면 마켓 인앱 결제를 써야 합니다. 지금은 유료 상품이 없고, 만들 때 별도 판단합니다.
- **⛔ 앱 출시 때 게임별 필수 항목**(마켓 앱을 만들 때 아래를 빠짐없이 넣는다. 게임 README 의 "앱 출시 때 필수"에도 적혀 있음):
  - **타임 투 플립 — 게임 판 화면 캡처 막기(치팅 방지)**: 카드를 캡처해 두고 보며 맞히는 것을 막는다. 웹(지금)은 막을 방법이 없어 앱에서만 한다.
    - 안드로이드: 게임 판(미리 보기·플레이) 동안만 `FLAG_SECURE` 를 켜 캡처·화면 녹화가 검게 찍히게 하고, 시작·결과 화면에서는 끈다(결과 공유 이미지는 앱 안에서 그려 만들어 영향 없음). TWA(크롬으로 띄움)는 이 설정을 할 수 없으므로 이 게임이 들어가는 앱은 Capacitor 같은 웹뷰 앱으로 감싼다.
    - iOS: 캡처를 막을 수 없다. 화면 녹화·미러링 중(`UIScreen.isCaptured`)이면 게임 판을 가리고, 스크린샷 알림(`userDidTakeScreenshotNotification`)을 받으면 그 판은 랭킹에 올리지 않는다.
    - 웹과 앱의 연결점(예: 앱이 `Joypack` 에 `setSecure(on)`·`onCaptured` 를 넣어 주고 게임은 판 시작·끝에서 부름)은 앱을 만들 때 공통 모듈로 정한다.
- 게임을 새로 공개하면(7.4) 마켓 앱도 갱신이 필요한지 확인합니다(웹 내용만 바뀌면 TWA 는 대개 다시 올리지 않아도 되지만, 앱스토어는 큰 기능 변화를 심사 대상으로 봄).

### 10.7 광고 넣는 자리 (광고를 붙일 때)

- **게임 중(손으로 조작하는 동안)에는 광고를 띄우지 않습니다**. 실수 클릭을 부르는 배치는 광고 정책 위반입니다.
- 넣는 곳: 결과 화면 아래 배너, 허브 첫 화면 목록 아래 배너, 판과 판 사이 전면 광고(몇 판에 한 번만), 보상형은 사용자가 고를 때만.
- 광고가 버튼(다시 하기·홈·등록)과 붙지 않게 여백을 두고, 위 메뉴·다이얼 같은 조작 영역을 가리지 않습니다.
- 광고 자리를 만들면 7.1 화면 크기 점검에 그 자리를 넣은 화면을 추가합니다.

## 11. 첫 버전 품질 기준 — 게임성·디자인·제작자 성향 (필수, 문서 1.49부터)

타임 투 플립은 이 문서대로 만든 첫 버전(v0.1.0) 뒤에 **고친 커밋이 45개 넘게** 이어졌습니다(11.7). 플랫폼 계약(1장)은 처음부터 지켰지만, **게임성·디자인·제작자 취향**의 기준이 문서에 없어 "아동틱하다, 이게 필요해?, 깜박인다, 이해가 안 된다"를 사람이 하나씩 찾아 고쳤습니다. 이 장은 그 수정들과 업다운·두더지잡기 분석에서 뽑은 기준입니다. **새 게임은 첫 버전부터 이 장을 통과한 상태로 보여 줍니다**(0장 2·6단계).

### 11.2 게임성 설계 (코드 전에 "재미 설계" 표를 README 에)

세 게임에서 재미가 난 곳은 같습니다. 두더지잡기 README 의 **재미의 세 기둥**을 모든 게임의 뼈대로 씁니다.

| 기둥 | 질문 | 업다운 | 두더지잡기 | 타임 투 플립 |
| --- | --- | --- | --- | --- |
| **손맛** | 누를 때마다 몸으로 느껴지나 | 다이얼 눈금 톡·방향 진동 | 히트 스톱·납작 눌림 | 3D 뒤집기·콤보 음계 |
| **판단** | 매 순간 고를 것이 있나 | 반씩 좁히기, 온도계를 쓸까(−300점) | 칠 것·피할 것(폭탄) | 본 카드 기억 vs 탐색 |
| **욕심** | 한 판 더 하게 만드나 | 범위별 랭킹, 정석보다 적게 | 콤보 → 피버, 미션, 도감 | 판 오르기, 도감 48장, 오늘의 챌린지 |

필수로 정해 README "재미 설계"에 적습니다.

1. **한 판 길이와 끝**: 보통 실력 1~3분, 고수도 5분 안팎에서 끝나게. "끝없이 이어지는 판"이면 **높은 판에서 얻는 것을 줄여 반드시 끝나게** 합니다(타임 투 플립 9판부터 얻는 시간 −10%/판).
2. **난이도 곡선**: 처음 1판은 규칙만 익히는 쉬운 판(실수 벌 없음, 구분이 쉬운 색·모양), 판마다 **새 요소 하나**(특수 카드·닮은 카드·폭탄…)를 차례로 등장시키고 그 판 위쪽에 짧게 알립니다. 어려움은 "보는 시간을 짧게"보다 **내용을 어렵게**(닮은 그림, 색 없는 그림, 더 많은 장)로 올리고, 사람이 반응할 수 없을 만큼 짧은 시간은 두지 않습니다.
3. **모의 플레이로 수치 맞춤**: 규칙을 `src/game/` 에 두고 실력별(서툼·보통·잘함·고수) 자동 플레이 테스트(`tests/balance.test.ts` 본보기)로 평균 판 수·시간을 재서 README 에 적습니다. 감으로 정한 수치로 첫 버전을 내지 않습니다.
4. **점수는 실력**: 운으로 얻은 것(황금 카드 등)은 점수 재미로만 쓰고 **기록(★ 개수 등)으로 남기지 않습니다**(도감에는 효과 설명 칸만). 대신 노릴 수 있게 판 위에서는 또렷하게 보여 줍니다(타임 투 플립 황금 카드: 금 액자 + ★, 외우는 시간에 보고 자리를 기억하면 2배). 점수식은 서버 규칙이 상한을 검사할 수 있게 단순하게(업다운 점수식 = 서버 검사식).
5. **선택이 있는 도움**: 도움 기능은 공짜가 아니라 대가가 있는 선택(업다운 온도계: 한 판 1번·점수 차감·조건부). 자동으로 다 알려 주지 않습니다.
6. **치팅 막기**: 오늘의 챌린지는 같은 판이어도 **재시도마다 위치를 섞어** 외워 풀 수 없게, 일시정지 중에는 판을 가림, 랭킹 점수는 서버 규칙으로 상한·공개 시각 검사. 웹에서 못 막는 것(캡처)은 README "앱 출시 때 필수"에 적습니다.
7. **재도전 장치**: 게임 중 **빠른 재시작**, 결과 화면 "다시 하기" 한 번 누름, 결과에 "다음 목표"가 보이게(최고 기록·다음 순위·새로 모은 것).
8. **수집**: 도감·수집 요소가 있으면 못 연 칸은 잠가 두어 "보고 싶다"를 남깁니다(전부 보여 주지 않음).

### 11.3 디자인 기준 (첫 버전부터)

- **대상은 어른도 즐기는 세련된 캐주얼.** 그림책·유치원 느낌(굵은 원색 웃는 얼굴 남발, 과일·별 스티커, 크레용)은 게임 소재가 정말 그것일 때만. 기본은 **진한 바탕 + 또렷한 강조색 + 금빛·빛 포인트**, 그라데이션·안쪽 빛·그림자로 **입체감**. 단색 납작한 아이콘·카드로 끝내지 않습니다.
- **로고 = 게임 시연**: 제목 글자 + 게임의 핵심 동작을 몇 초 동안 보여 주는 작은 연출(타임 투 플립 카드 세 장 시연, 업다운 ▲▼ 튐, 두더지잡기 망치 오프닝). 시연은 **규칙을 오해하지 않게 실제 규칙대로**(틀리면 둘 다 덮기). 시작 화면에서 크게(타임 투 플립 v0.15 시작 화면 로고가 기준), **결과 화면 위에도 같은 크기로** 둡니다(결과 화면이 비어 보이지 않게).
- **허브 아이콘 = 로고와 같은 그림**(약식으로 다른 그림 금지), 아이콘 바탕은 허브 카드 색과 구분(6장 1번 검사).
- **게임 위쪽 정보(HUD)**: 판·점수·콤보·시간을 한 판(반투명 유리판 하나)에 이름표 + 고정폭 숫자로 정리. 따로 떠 있는 알약 여러 개로 흩지 않습니다.
- **시간·진행은 그림으로**: 남은 시간은 막대 + 끝을 따라가는 아이콘(0초에 끝까지, 밖으로 나가지 않게), 외우는 시간·준비 시간도 같은 막대로 보여 줌. 숫자만 두지 않습니다.
- **크기·여백**: 로고·게임명·주요 버튼은 넉넉히 크게, 상자 안 위아래 여백은 답답하지 않게(타임 투 플립 랭킹 등록 완료 상자 v0.3.2), 닫기 버튼은 창 바탕보다 한 톤 진한 바탕 + 테두리 + 굵은 X(모든 창 같게).
- **배치가 흔들리지 않게**: 등록 전·후, 문구 길이, 한·영 전환으로 카드·버튼 높이가 바뀌지 않게 높이를 고정하거나 자리를 미리 잡습니다. 제목이 두 줄이 될 때 줄 사이도 확인합니다.
- **깜박임 0**: 1.10 "화면보다 큰 움직이는 층 금지·캔버스 한 장"을 처음부터 지킵니다. 휴대폰에서만 보이므로 의심되면 휴대폰 화면 녹화로 확인합니다.
- **민감 요소**: 국기·정치·종교를 떠올리게 하는 상징(흰 바탕 빨간 원, 욱일 모양 빛살 등)과 특정 나라 작품 쏠림을 피합니다. 명화·작가를 쓰면 나라를 고르게 섞습니다.
- **카드·그림 세트**: 초반은 색·모양 차이가 큰 단순한 그림, 뒤로 갈수록 화풍이 깊어지게(도형 → 팝아트 → 명화 → 수묵화처럼). 같은 세트 안에서는 그림체를 통일합니다.

### 11.4 모든 요소에는 이유가 있다

- 화면에 넣는 요소·기능마다 README 에 **"무엇을 위한 것인지" 한 줄**을 적을 수 있어야 합니다(재미의 세 기둥 중 무엇, 또는 이해를 돕는지). 적을 수 없으면 넣지 않습니다.
- 꾸밈만 하는 카드·스티커, 누르면 테두리만 생기는 선택, 의미 없는 기록(운으로 얻은 ★), 설명 없는 아이콘은 넣지 않습니다.
- 문구는 **행동을 알려 주는 짧은 말**로: "위치를 기억하세요", "닮은 카드 주의!". 판 번호·숫자를 섞은 애매한 문구는 피합니다.

### 11.5 출시 전 확인 도구 (첫 버전부터 함께)

새 게임은 처음부터 공용 `Joypack.devMode()`·`Joypack.devJump()`·`Joypack.devTools()`·`Joypack.setReleaseView()` 로 아래를 넣습니다(본보기: 타임 투 플립 README "출시 전 확인용").
- **판 바로가기(판 바로 시작·모든 판 열기)는 `devJump()`**: 개발자 모드이고 "출시 화면" 보기가 꺼져 있으면 **정식 공개 뒤에도 보입니다**(출시 뒤 문제 확인용). 그래서 바로가기로 시작한 판은 반드시 최고 기록·랭킹에 남기지 않습니다. "TEST" 칸과 출시 화면 단추는 `devMode()` 일 때 보입니다.
- 도감·수집 전부 열기 등 나머지 확인 기능은 `devTools()`(미리보기 배포일 때만, 정식 공개하면 사라짐). 단, 이미 정식 공개한 게임에 나중에 확인 도구를 더할 때는 `devJump()` 로 둡니다(예: 두더지잡기 도감 모두 열기, v1.0.5).

- **"TEST 판 바로 시작"**(판·단계 골라 바로 시작) 또는 **모든 판 열기**(판·단계가 있는 게임), 도감·수집 **전부 열기**, **출시 화면** 보기 단추(확인 도구를 숨겨 실제 화면 확인)
- **자리: 설정 창 맨 위 "TEST" 칸**(제목 바로 아래, 테마보다 위). 판 바로가기 단추와 출시 화면 단추를 이 칸에 함께 둔다. 시작 화면 로고 위에 띄우면 작은 화면에서 위 메뉴·로고와 겹치고, 설정 맨 아래에 두면 테스트할 때마다 스크롤해야 한다(본보기: 타임 투 플립·온실정원 `settingsPanel`)
- 게임 중 **빠른 재시작**(이것은 출시 뒤에도 남는 일반 기능)

### 11.6 첫 버전 자체 검수 (보여 주기 전에 모두 "예")

7장 완료 검사와 함께, 첫 버전을 사람에게 보이기 전에 대표 화면(시작·게임 중·결과·도감) 캡처를 직접 보며 확인합니다.

- [ ] **유아틱하지 않은가**: 어른이 휴대폰에 깔아 두고 싶은 그림인가? 납작한 단색으로 끝난 곳은 없나?
- [ ] **의미 없는 요소가 없나**: 화면의 모든 요소에 이유 한 줄(11.4)이 있나?
- [ ] **처음 보는 사람이 바로 아나**: 로고 시연·안내 문구·시간 표시가 오해 없이 읽히나?
- [ ] **끝이 나나**: 모의 플레이로 실력별 평균 판 수·시간을 쟀고, 고수도 5분 안팎에 끝나나?
- [ ] **어려움 곡선**: 1판은 쉽고, 판마다 새 요소가 하나씩 오고, 높은 판도 반응할 수 있는 시간인가?
- [ ] **치팅**: 재시도로 외우기·일시정지로 외우기·점수 조작이 막혔나?
- [ ] **재도전**: 빠른 재시작·다시 하기·다음 목표가 있나?
- [ ] **크기**: 로고·게임명이 시작·결과 화면 모두 크게, 닫기 버튼이 잘 보이나?
- [ ] **배치 고정**: 랭킹 등록 전후·한영 전환에 높이가 변하지 않나?
- [ ] **깜박임**: 큰 움직이는 층이 하나(캔버스)뿐인가?
- [ ] **민감 요소**: 국기·정치 연상, 특정 나라 쏠림이 없나?
- [ ] **아이콘 = 로고**, 출시 전 확인 도구(11.5)가 있나?

첫 버전 보고에는 대표 화면 캡처 한 장(모음 그림), 모의 플레이 수치, 그리고 **바꿀 만한 큰 결정 3가지**(예: 로고·그림체·배경)와 각각의 대안을 한 줄씩 적습니다. 사람이 고르면 그때 시안 이미지(3~5개)를 만듭니다. 처음부터 시안을 여러 개 만들지는 않습니다(토큰 절약).
